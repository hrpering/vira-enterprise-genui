# PR-054: React Thin Wrapper

## Goal
Turn the React placeholder into a thin lifecycle wrapper over the public Runtime Web SDK without creating a second GenUI implementation or React-owned RuntimeState mirror.

## Scope
- Add React 18.2–19.x peer support, developed against React 19.2.
- Add `<ViraExperience />` implemented without JSX-specific runtime assumptions.
- Create/dispose the exact public `createViraGenUI` SDK from a React effect.
- Mount the supplied experience through the SDK and return `null`; the configured Runtime Web DOM Port remains the renderer/target owner.
- Forward SDK action/effect/statechange/error notifications to optional React callbacks.
- Expose the exact active SDK through an imperative `ref.getSdk()` handle rather than reimplementing dispatch/patch APIs.
- Keep callback prop changes live without forcing SDK remount; configuration/experience identity changes intentionally dispose and remount.
- Add a private lifecycle-session helper with contract tests.

## Out of scope
- React `useState` mirror of RuntimeState.
- React component rendering of semantic regions/components.
- duplicated permission/reducer/action logic.
- automatic effect execution.
- Web Component dependency.
- router/state-management integrations.

## Acceptance criteria
- `react` depends internally only on `runtime-web`.
- no planner/composer/runtime-core/web-component imports exist.
- RuntimeState remains owned by the Runtime Web SDK; React keeps only an SDK reference.
- component renders `null` and performs no alternate DOM rendering.
- effect cleanup disposes the exact SDK created by that effect.
- callback exceptions are contained and cannot alter Runtime Web results.
- configuration/experience identity changes create a fresh SDK lifecycle; callback identity changes alone do not.
- subscription effects remain notifications only.

## RE/QC focus
Look for React-owned task state, duplicated runtime logic, direct lower-layer imports, effect execution, render-tree implementation, stale SDK refs after cleanup, callback props in remount dependencies, hidden browser globals, or wrapper APIs that diverge from the public Runtime Web SDK.
