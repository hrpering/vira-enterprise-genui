# PR-038: Runtime Web User Event Bridge

## Goal
Convert validated enterprise UI events into canonical RuntimeAction values while fixing action source to `user` and keeping identity generation outside Adapter SDK.

## Scope
- Add trusted RuntimeWebActionIdFactory interface.
- Add `createUserActionFromEvent(input, idFactory)`.
- Validate exact Action Adapter event mapping first.
- Call ID factory only after event validation succeeds.
- Construct final RuntimeAction through Runtime Core with `source: "user"`.
- Reject root `id`, `source`, permission, or execution fields.
- Contain ID-factory exceptions/raw values.
- Return Runtime Core's immutable RuntimeAction.

## Out of scope
- DOM event listener registration.
- Host/system action bridges.
- Permission evaluation/reducer execution.
- Effect execution/network/tool calls.
- Retry/queue behavior.

## Acceptance criteria
- Adapter/event input cannot spoof RuntimeAction source or ID.
- Browser bridge source is always `user`.
- Invalid/unmapped event never consumes an action ID.
- Bad/throwing ID factory fails closed without raw exception reflection.
- Runtime Core owns final action validation.
- No reducer/permission/effect execution occurs here.

## RE/QC focus
Look for source/id spoofing, ID consumption before validation, adapter privilege leakage, raw factory exception reflection, action execution, permission bypass, mutable payloads, or RuntimeAction validation duplication.
