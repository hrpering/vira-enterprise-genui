## Reverse-engineering baseline

`@vira-enterprise-genui/experience-packs` already owns the canonical distribution manifest:

- `id` and release-semver `version`;
- publisher identity/name;
- human metadata/tags;
- Vira compatibility range;
- entrypoints;
- content-addressed artifact descriptors;
- canonical fail-closed `parseExperiencePackManifest()`;
- deterministic `serializeExperiencePackManifest()`.

Registry must not create a second Pack schema, artifact descriptor model, publisher model, compatibility model, or media type.

## Goal

Add a bounded, provider-neutral, persistence-free Registry snapshot contract over canonical Experience Pack manifests.

```text
bounded Registry JSON text
      ↓
pre-parse structural budget
(containers + structural tokens)
      ↓
captured JSON.parse()
      ↓
iterative null-prototype detach
      ↓
existing parseExperiencePackManifest()
      ↓
canonical Pack manifests
      ↓
identity-marked Experience Registry snapshot
      ↓
exact primitive id + version lookup
```

## V1 scope

- immutable versioned snapshot;
- maximum 256 manifests per snapshot;
- every manifest validated by the existing Experience Packs parser;
- duplicate `(id, version)` pairs rejected;
- deterministic ordering by exact `id`, then exact `version` string;
- exact lookup by primitive `id + version` only;
- lookup returns the canonical `ExperiencePackManifest` or `null` when absent.

V1 intentionally has no `latest`, semver-range resolution, channels, aliases, mutable lifecycle state, ranking, popularity, download counts, installation state, persistence, remote fetch, authentication, or marketplace semantics.

## Review-driven untrusted-data boundary

Initial review found that a reflective object-graph preflight could not honestly guarantee no Proxy trap execution: generic JavaScript reflection can itself hit Proxy traps. Later review found inherited-state, mutable-intrinsic and resource-amplification risks around JSON parsing and graph detachment.

REG-001 therefore uses a bounded JSON-text ingress:

- input text length is capped at 16,000,000 characters;
- a constant-memory lexical scanner runs before parsing;
- at most 100,000 object/array openings are allowed;
- at most 500,000 `{`, `[`, `,`, `:` structural tokens are allowed;
- structural characters inside quoted JSON strings do not consume those budgets;
- the scanner is resource gating only, not a second JSON parser;
- `JSON.parse` and Registry-owned detachment/control-flow intrinsics are captured at module initialization;
- parsed manifest graph detachment keeps a 100,000-container defense-in-depth budget;
- every parsed object is detached to null prototype before Pack validation;
- Pack semantics are delegated exclusively to `parseExperiencePackManifest()`;
- successful snapshot objects are recorded in a module-private canonical identity set using protected intrinsics;
- exact lookup accepts only one of those canonical snapshot identities and primitive id/version strings;
- lookup uses one independent 4,096-character safety bound rather than reproducing Pack grammar maxima;
- Registry-owned ordering and lookup do not trust ambient Array/WeakSet/String prototype methods.

XP-002 separately guarantees that canonical Pack output itself is prototype-independent, uses protected freeze/canonicalization intrinsics, and cannot lose array writes through inherited numeric setters. Those are Pack-owner properties, not Registry-local validation rules.

## Privacy/error posture

Nested Pack validation failures are normalized to the manifest index and do not echo arbitrary rejected property names or Pack/customer content through Registry errors.

JSON parse and structural-budget errors are generic. Exact lookup queries are data-only primitive strings and are never interpreted as URLs, paths, selectors, regexes, or executable expressions.

## Package boundary

```text
experience-registry -> experience-packs
```

No other internal production dependency is permitted.

## Explicit non-goals

Do not:

- store artifact bytes;
- add filesystem/database/object-store access;
- add OCI/ORAS network transport;
- create registry HTTP endpoints;
- invent a second Pack digest/media type;
- resolve mutable tags such as `latest`;
- implement marketplace search/ranking/reviews;
- add publisher authentication or signing;
- depend on Studio runtime, React/Puck, Policy Engine, Observability, Marketplace, or Protocol Gateway.

## Acceptance direction

1. exact canonical Pack parser delegation;
2. no copied Pack field validation;
3. deterministic immutable snapshot;
4. duplicate id/version rejection;
5. exact lookup hit and miss;
6. malformed Pack remains an error, never a Registry entry;
7. arbitrary object/Proxy input rejected before reflection;
8. bounded serialized ingress before JSON parsing;
9. container amplification rejected before `JSON.parse()`;
10. primitive-array/object structural amplification rejected before `JSON.parse()`;
11. structural characters inside JSON strings do not consume the resource budget;
12. ambient `JSON.parse` mutation does not control parsing;
13. parsed JSON object prototypes detached before Pack validation;
14. canonical snapshot identity required for lookup;
15. lookup safety bound independent from Pack syntax limits;
16. nested validation errors sanitized;
17. dependency boundary only to `experience-packs`;
18. Pack-owner prototype/intrinsic requirements are supplied by frozen XP-002 rather than duplicated here;
19. exact stacked-head repository verification before final integration.
