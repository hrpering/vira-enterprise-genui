# PR-025: Composition Engine

## Goal
Compose validated planner priority with explicit layout/disclosure policies into one immutable semantic ComposedExperience without duplicating task state or entering rendering ownership.

## Scope
- Strictly read public engine input: plan/layout/disclosure.
- Derive priority through Planner's `planComposition` owner.
- Validate explicit layout/disclosure through their owning Composer policies.
- Create non-empty primary/supporting/deferred semantic regions from planner buckets.
- Preserve Disclosure Policy once at top level as the single visibility source of truth.
- Return immutable planId/mode/layout/disclosure/regions artifact.
- Add integration tests and documentation.

## Out of scope
- Task-state/DomainData duplication in composed output.
- Component/brand mapping.
- Actions/runtime effects.
- DOM/CSS/responsive geometry.
- Model/network behavior.

## Acceptance criteria
- Planner remains source of semantic priority; engine does not reimplement ranking.
- Layout/disclosure remain explicit; no defaults.
- Empty semantic buckets are omitted rather than producing empty regions.
- Disclosure is not duplicated per region; consumers resolve it by region role.
- Task state is not copied into ComposedExperience.
- Caller-owned plan/policy/capability objects are not retained mutably.
- Public error paths map to plan/layout/disclosure surfaces.
- Output is frozen/serializable and contains no rendering/execution fields.

## RE/QC focus
Look for duplicated planner logic, hidden layout/disclosure defaults, disclosure/state duplication, mutable input retention, incorrect role/policy semantics, empty regions, component/DOM/action leakage, cross-package dependency inversion, or error-path ambiguity.
