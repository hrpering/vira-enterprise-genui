# PR-060: Tool Bridge Golden Integration Gate

## Goal
Close the Tool Bridge phase with a deterministic test/docs-only gate proving that custom canonical, MCP, and LangChainJS tool-result surfaces converge on the same Protocol DomainData semantics without provider leakage or unsafe text parsing.

## Scope
- Exercise direct custom `ExternalToolResult` parsing.
- Exercise the MCP `CallToolResult` adapter.
- Exercise the LangChainJS `ToolMessage` adapter.
- Normalize all three successful structured results into the same domain/type/data shape with provider-specific source identity only.
- Exercise explicit freshness classification for canonical results and `unknown` for provider results without freshness.
- Verify provider error content/call IDs/metadata do not survive normalization.
- Document the deliberate OpenAI Responses boundary: current `function_call_output.output` is string or text/image/file content, so Vira does not parse JSON-looking text into GenUI data.
- Add tests/docs only.

## Explicitly out of scope
- production source changes.
- OpenAI string-to-JSON parsing.
- provider SDK dependencies.
- tool execution/network calls.
- data transforms/selectors.
- retry/cache policy.

## Acceptance criteria
- PR changes only tests/docs.
- three integration surfaces produce canonical validated results.
- structured success converges on identical DomainData domain/type/data semantics.
- source identity preserves which bridge produced the data without provider metadata leakage.
- raw provider error content never appears in canonical failures.
- no JSON-looking string is treated as structured data.
- freshness remains explicit-clock observation only.

## RE/QC focus
Look for hidden production changes, provider SDK imports, provider metadata leaking into DomainData, string-to-JSON parsing, fake data on unstructured results, error-content leakage, freshness policy/execution, or tests that bypass public Tool Bridge APIs.
