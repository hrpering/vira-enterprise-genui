# PR-010: Runtime state

## Goal
Create the minimal immutable runtime state container without duplicating task state or prematurely introducing lifecycle, permissions, or errors.

## Scope
- Define `RuntimeState` with `experienceId`, `revision`, and one canonical `ExperiencePlan`.
- Use `ExperiencePlan.state` as the single task-state source of truth; do not create a parallel `taskState` field.
- Validate and clone incoming plans through Protocol before storing them.
- Deep-freeze runtime state so callers cannot mutate nested plan/state/capability data in place.
- Start deterministic revision numbering at zero.
- Declare the runtime-core -> protocol workspace dependency and package export surfaces required for internal package imports.
- Add contract tests and documentation.

## Out of scope
- Runtime actions/reducer behavior.
- Patch application.
- Lifecycle states.
- Permissions.
- Error taxonomy.
- Browser, DOM, React, network, telemetry, or customer behavior.

## Allowed files
- `packages/runtime-core/src/state/**`
- `packages/runtime-core/src/index.ts`
- `packages/runtime-core/package.json`
- `packages/protocol/package.json`
- `tests/contract/runtime-state.test.ts`
- `docs/runtime-core/state.md`
- `docs/pr-plans/PR-010.md`

## Acceptance criteria
- Valid ExperiencePlan input produces revision `0` runtime state.
- Stored plan and nested data are cloned from caller-owned objects and frozen recursively.
- Invalid experience IDs or plans fail deterministically without throwing for ordinary validation errors.
- Runtime state is JSON serializable.
- There is no duplicate `taskState` field; `state.plan.state` is the current resolved task state.
- No lifecycle/permission/error/action semantics are invented early.
- runtime-core imports protocol only through the workspace package name, and package-boundary verification remains satisfied.

## RE/QC focus
Look for duplicated state ownership, mutable nested references, runtime/browser leakage, hidden globals, random/time-based initialization, premature lifecycle/permission/error fields, cross-package relative imports, and validation bypasses.
