# PR-046: Public Web SDK Configuration

## Goal
Create one normalized configuration boundary for the public Web SDK while keeping executable DOM/ID integrations explicit trusted ports.

## Scope
- Add `createWebSdkConfiguration(input)`.
- Normalize ComponentAdapter, ActionAdapter, RuntimePermissionPolicy, AccessibilityPolicy, and ResponsivePolicy through owning validators.
- Promote AccessibilityPolicy parsing to its owning public validator so SDK creation does not duplicate its rules.
- Validate trusted DOM Port and Action ID Factory method shapes without executing getters or methods.
- Snapshot/bind trusted executable methods into frozen wrappers so replacing caller methods after configuration cannot silently change the SDK boundary.
- Reject unknown configuration fields and fail closed with stable paths.

## Out of scope
- `createViraGenUI` instance lifecycle.
- mounting or event processing.
- effect execution.
- concrete browser DOM implementation.
- network/tool/model calls.
- mutable policy hot swapping.

## Acceptance criteria
- Every data-only config surface is normalized by its owning package.
- Accessibility rules have one owner and existing accessible-render behavior is preserved.
- Trusted executable methods are inspected by descriptors and are not invoked during configuration.
- Getter-backed executable fields fail closed without getter execution.
- Caller mutation of data configs or replacement of trusted methods after creation does not alter the returned configuration.
- Configuration and normalized data are frozen.

## RE/QC focus
Look for duplicated policy validation, getter execution, trusted method invocation during creation, caller-reference retention, privilege defaults, hidden browser globals, effect/network execution, path attribution bugs, or a second source of accessibility truth.
