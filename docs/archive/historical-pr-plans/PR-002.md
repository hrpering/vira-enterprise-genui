# PR-002: Enforce package dependency boundaries

## Goal
Turn the architectural dependency rules from PR-001 into executable verification.

## Scope
- Add one canonical package-boundary configuration.
- Validate declared internal workspace dependencies.
- Validate internal imports found in package source files.
- Reject forbidden dependency directions.
- Reject undeclared internal imports and unknown internal packages.
- Reject relative imports that reach across package roots.
- Reject duplicate internal package names.
- Detect circular package dependencies.
- Add the boundary check to the root `verify` command.
- Add focused positive and negative tests for the validator.

## Out of scope
- Product/runtime behavior.
- Protocol type implementation.
- Browser or React behavior.
- Third-party dependency vulnerability scanning.
- Customer- or domain-specific policy.

## Allowed files
- `package.json`
- `tooling/package-boundaries.config.mjs`
- `tooling/check-package-boundaries.mjs`
- `tooling/check-package-boundaries.test.mjs`
- `docs/pr-plans/PR-002.md`

## Acceptance criteria
- The current workspace passes the checker.
- `protocol -> runtime-web` is rejected.
- `runtime-core -> protocol` is allowed when declared.
- An internal import without a package declaration is rejected.
- A relative cross-package source import is rejected.
- Duplicate internal package names are rejected.
- Circular internal package dependencies are rejected.
- No package implementation logic is introduced.

## RE/QC focus
Confirm that the validator enforces the documented architecture rather than introducing a second contradictory dependency model. Verify that the tool has no network access and cannot mutate workspace files. Confirm that relative-path imports cannot bypass the package graph.
