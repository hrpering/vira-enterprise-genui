# PR-024: Disclosure Policy

## Goal
Define explicit semantic disclosure policy with invariants that prevent current primary work from being hidden or deferred work from being promoted implicitly.

## Scope
- Define immediate/progressive/on-demand/hidden semantic disclosure levels.
- Require explicit disclosure decisions for primary/supporting/deferred roles.
- Require primary = immediate.
- Reject supporting = hidden.
- Reject deferred = immediate.
- Reject UI implementation fields.
- Return frozen serializable policy data.

## Out of scope
- Accordion/collapse widgets.
- DOM/CSS visibility implementation.
- Responsive behavior.
- Components/brand styling.
- Layout family selection.
- Runtime actions/permissions.

## Acceptance criteria
- Primary task capabilities cannot be hidden.
- Supporting capabilities cannot be fully suppressed.
- Deferred capabilities cannot be silently promoted to immediate.
- All role decisions are explicit; no defaults.
- UI implementation fields are rejected.
- Output is immutable and serializable.

## RE/QC focus
Look for primary-task hiding, deferred-priority promotion, hidden defaults, UI widget/CSS leakage, ambiguous levels, mutable policy values, or accessibility-sensitive behavior being encoded as implementation rather than semantics.
