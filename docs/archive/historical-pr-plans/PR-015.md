# PR-015: Runtime error taxonomy

## Goal
Define deterministic serializable runtime-core error data without importing error ownership from planner/composer/renderer or carrying caller-controlled messages/raw exception objects.

## Scope
- Define canonical runtime-core error codes and derived categories/messages.
- Create strict bounded frozen RuntimeError values.
- Reject caller-supplied category/message and arbitrary raw detail fields.
- Exclude stacks, causes, exceptions, timestamps, HTTP status codes, and executable data.
- Add contract tests and documentation.

## Out of scope
- Planner/composer/adapter/renderer/security error taxonomies.
- Logging/telemetry sinks.
- Exception stack serialization.
- Localization/user-facing copy.
- Reducer error mapping (PR-016).

## Acceptance criteria
- Known codes map deterministically to categories and fixed messages.
- Callers cannot override category or message.
- Error values are frozen and JSON serializable.
- Unknown codes and unsafe/unbounded paths are rejected.
- Raw exception/stack/cause/timestamp/detail fields are rejected.
- Runtime-core does not import planner/composer/renderer ownership.

## RE/QC focus
Look for raw exception/PII leakage, arbitrary detail bags, caller-controlled messages/category/severity, user-facing HTML assumptions, mutable errors, hidden timestamps, HTTP/framework coupling, or cross-package error ownership leakage.
