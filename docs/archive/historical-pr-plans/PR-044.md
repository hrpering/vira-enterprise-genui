# PR-044: Runtime Web Render Model Lookup Performance

## Goal
Remove repeated full Component Adapter validation/scanning from RenderModel preparation while preserving the exact semantic contract and fail-closed behavior.

## Scope
- Validate ComponentAdapterContract exactly once per `prepareRenderModel` call.
- Build one local capability-id -> semantic component-reference lookup index from the validated contract.
- Resolve composed capabilities through exact O(1) lookup.
- Preserve region/capability order and existing unmapped-component failures.
- Add a canonical maximum-capability regression test without wall-clock timing assertions.

## Out of scope
- caching across requests/sessions.
- changing Component Adapter public API.
- fallback component selection.
- component implementation/loading.
- render props/data binding.
- DOM/runtime behavior.

## Acceptance criteria
- No per-capability Component Adapter revalidation occurs inside `prepareRenderModel`.
- Exact capability identity remains the only lookup key.
- Missing mappings still fail closed at the existing composed-capability path.
- Canonical maximum capability count prepares successfully when every mapping exists.
- Capability/region ordering remains unchanged.
- No new public API or semantic behavior is introduced.

## RE/QC focus
Look for duplicated adapter validation, linear rescans inside the capability loop, fallback mapping, map-key ambiguity, ordering drift, bypass of the owning adapter validator, mutable index/output, or customer-specific shortcuts.
