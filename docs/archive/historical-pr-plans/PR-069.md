# PR-069: Telemetry Channel Lifecycle

## Goal
Add the minimal bounded lifecycle layer that validates canonical telemetry events before exporter invocation and closes telemetry admission deterministically during shutdown.

## Scope
- Add immutable `TelemetryChannel` with `emit`, `emitBatch`, `flush`, `shutdown`, and `getState`.
- Revalidate unknown event input through the canonical Telemetry event contract.
- Bound batch size before recursive event validation.
- Reject sparse, accessor-backed, custom-property, and symbol-bearing batch input without invoking getters.
- Snapshot normalized events into a fresh frozen batch before exporter invocation.
- Use explicit single-flight concurrency with fail-closed `CHANNEL_BUSY` instead of an implicit queue.
- Model `open -> closing -> closed` channel lifecycle.
- Close event admission immediately on first shutdown request.
- Wait for already accepted work, then call exporter flush and shutdown exactly once.
- Make shutdown idempotent and attempt exporter shutdown even when flush fails.
- Preserve generic provider-failure redaction from the exporter port.
- Add contract tests and documentation.

## Explicitly out of scope
- background workers or timers.
- unbounded or persistent queues.
- retry/backoff.
- exporter/provider-specific adapters.
- OpenTelemetry/OTLP dependencies.
- automatic event generation or instrumentation of other packages.
- generated IDs, hidden clocks, trace/span propagation.
- prompt/message/domain-payload/user-identifier collection.

## Acceptance criteria
- invalid events never reach exporter code.
- oversized batches fail before per-event parsing.
- accessor-backed batch indexes are rejected without getter execution.
- caller batch mutation cannot change accepted exporter input.
- concurrent emit/flush calls fail with `CHANNEL_BUSY`; no hidden queue is built.
- shutdown switches admission to closed immediately while allowing accepted work to finish.
- exporter flush then shutdown are each invoked at most once by channel shutdown.
- shutdown is idempotent and cleanup still attempts shutdown after flush failure.
- provider errors expose only generic operation-level failure data.
- channel object is frozen and Telemetry remains dependency-free.

## RE/QC focus
Look for event-validation bypasses, getter execution, oversized work before bounds, mutable batch retention, hidden queues, operations admitted after shutdown begins, duplicate cleanup, retries, provider error leakage, hidden clocks/IDs, or vendor dependencies.
