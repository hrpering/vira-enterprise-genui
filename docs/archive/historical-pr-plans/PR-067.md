# PR-067: Telemetry Event Contract

## Goal
Create the minimal provider-neutral telemetry event envelope with privacy-safe defaults and deterministic caller-owned time.

## Scope
- Add versioned `TelemetryEvent`.
- Add fixed source/kind/outcome enums.
- Require bounded lowercase machine event names.
- Require caller-supplied canonical UTC timestamps with millisecond precision.
- Permit only optional bounded finite numeric duration.
- Reject unknown, symbol, accessor-backed, raw-content, arbitrary-attribute, user-ID, payload, message, prompt, and trace fields.
- Return immutable normalized events.
- Export the Telemetry package public entry point.
- Add contract tests and documentation.

## Explicitly out of scope
- exporter/provider lifecycle.
- OpenTelemetry dependency or adapter.
- arbitrary attributes/tags.
- raw prompts/messages/domain data.
- user identifiers/PII.
- stack traces.
- trace/span IDs.
- hidden clock access or generated timestamps.
- generated event/correlation IDs.
- batching/network export.

## Acceptance criteria
- valid machine event is immutable and contains only approved fields.
- zero duration is preserved; omitted duration remains absent.
- privacy-sensitive/arbitrary fields fail as unknown.
- unsupported source/kind/outcome fail closed.
- noncanonical or invalid calendar timestamps fail.
- invalid/accessor-backed duration fails without getter execution.
- symbol/custom configuration state fails closed.
- Telemetry adds no runtime dependency.

## RE/QC focus
Look for arbitrary payload escape hatches, raw content/PII surfaces, hidden clocks, generated IDs, permissive timestamps, custom/accessor state, provider coupling, OpenTelemetry dependency leakage, mutable output, or exporter behavior mixed into the event contract.
