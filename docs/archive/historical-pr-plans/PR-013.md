# PR-013: Runtime lifecycle engine

## Goal
Add deterministic semantic lifecycle state to RuntimeState without coupling runtime-core to browser lifecycle or side effects.

## Scope
- Add `lifecycle` to RuntimeState with initial value `created`.
- Define semantic lifecycle states and an explicit transition matrix.
- Reject illegal/unknown transitions deterministically.
- Increment runtime revision exactly once on successful lifecycle transitions.
- Preserve lifecycle through plan patch updates.
- Keep terminal states cleanup-only (`disposed`).
- Add contract tests and documentation.

## Out of scope
- DOM/Web Component/React mounting behavior.
- Permission evaluation.
- Runtime action reducer/dispatch.
- Error taxonomy payloads.
- Host effects, network calls, retries, or telemetry.

## Acceptance criteria
- RuntimeState creation starts at `created`; no fake `idle` RuntimeState exists.
- Normal active/update/completion flow is deterministic.
- Cancellation/failure exits are explicit and terminal except disposal.
- Illegal transitions leave the current object unchanged.
- Successful transitions create a new frozen state and increment revision by one.
- Patch engine preserves lifecycle while updating plan state.
- No browser/framework/network concepts enter lifecycle.

## RE/QC focus
Look for browser lifecycle leakage, implicit side effects, hidden clocks/timers, lifecycle reset during patches, terminal-state resurrection, revision inconsistencies, or lifecycle state duplicated outside RuntimeState.
