## Reverse-engineering baseline

- `experience-packs` owns Pack identity/version/publisher/metadata/compatibility/artifacts and canonical Pack parsing.
- `experience-registry` owns canonical known Pack versions and exact lookup.
- Marketplace owns only curated public discovery projection.

Marketplace must never infer that every Registry entry is public and must never re-validate deserialized discovery entries as if it owned Pack semantics.

## Goal

```text
canonical Registry snapshot
      +
bounded listing-ref JSON text
      ↓
Experience Marketplace catalog builder
      ↓
private canonical catalog identity
      ↓
bounded query JSON text
      ↓
deterministic public discovery results
```

## Listing boundary

`createExperienceMarketplaceCatalog()` accepts:

1. a canonical Registry snapshot identity created by `parseExperienceRegistrySnapshot()`;
2. bounded JSON text representing an array of exact `{ id, version }` refs.

The listing JSON parser owns only the tiny ref wrapper shape. It does not validate Pack syntax. Every string ref is resolved through Registry exact lookup. Invalid lookup input fails as `INVALID_LISTING`; a syntactically acceptable but absent exact version is `MISSING_LISTING`.

Registry membership does not imply Marketplace listing. Only explicit refs become entries.

## Canonical catalog boundary

Successful catalogs are immutable and recorded in a module-private `WeakSet`.

Marketplace captures required `WeakSet` intrinsics at module initialization and invokes them through captured `Reflect.apply`, so ambient mutation of `WeakSet.prototype.add/has` cannot forge or suppress canonical identity.

`queryExperienceMarketplaceCatalog()` accepts only exact canonical catalog identities. It never structurally re-authorizes a serialized clone or hand-authored catalog.

## Public discovery projection

A Marketplace entry exposes only:

- Pack id/version;
- publisher id/display name;
- Pack display name/optional description/tags;
- Vira compatibility range.

It never exposes raw Pack manifests, artifact descriptors/digests/sizes, entrypoints, Studio publications, execution configuration, secrets, or provider/runtime data.

Projection reads optional Pack fields and array values only through own-data descriptors. Canonical entry objects are null-prototype frozen projections.

## Deterministic ordering and arrays

Marketplace-owned array logic does not depend on ambient `Array.prototype` iterator, `sort`, `includes`, or similar inherited behavior:

- tags are copied through own indexed data descriptors;
- entries are placed with deterministic manual insertion;
- duplicate checks and catalog traversal use own indexed data;
- tag filters use own indexed comparison.

Registry exact lookup remains owned by REG-001 and is consumed rather than duplicated.

## Query boundary

Query input is bounded JSON text containing only optional `text`, `publisherId`, `tag` and `limit` fields. Unknown fields fail closed through explicit exact comparisons. Strict TypeScript `noUncheckedIndexedAccess` is respected by checking every reflected query-field slot before dispatch.

The normalized query is a null-prototype own-data object. String trimming, case folding and substring matching use module-captured `String` intrinsics so ambient prototype mutation cannot change discovery semantics.

Filters are ANDed and preserve canonical catalog order. There is no regex, selector, SQL, shell, URL interpretation, scoring, relevance ranking, popularity, personalization, recommendations or paid placement.

## Review-driven hardening

The implementation was rebuilt after review found that arbitrary catalog objects created a second authority boundary. Subsequent adversarial reviews drove additional hardening:

- fake/deserialized catalog authority removed through canonical identity;
- caller-controlled duplicate/reversed order removed;
- JavaScript-only explicit `undefined` removed from untrusted ingress through JSON boundaries;
- inherited optional Pack/query fields removed through own-data/null-prototype normalization;
- ambient `Array.prototype` iterator/sort/includes dependencies removed;
- ambient `WeakSet`, `Set`, and `String` prototype dependencies removed from Marketplace-owned control flow;
- strict reflected-key TypeScript narrowing added for `noUncheckedIndexedAccess`;
- Registry exact lookup safety remains owned by REG-001 and Pack output safety by XP-002.
