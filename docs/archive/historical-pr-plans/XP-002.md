# XP-002 — Experience Pack parser and prototype hardening

This is an owner-level hardening follow-up to XP-001. Registry and Marketplace must consume this canonical Pack boundary rather than carrying duplicate Pack validation or sanitization.

## Reverse-engineering finding

`@vira-enterprise-genui/experience-packs` owns Pack v1 parsing, validation, canonicalization and deterministic serialization. Adversarial review found JavaScript ambient-state hazards in that owner boundary:

- inherited object properties could participate after validation when semantic code read the original object;
- sparse arrays could observe inherited numeric properties;
- canonical array writes could dispatch through inherited setters;
- accessor/symbol state and changing Proxy observations required snapshot semantics;
- parser/canonicalization code still dispatched through mutable ambient Array, Object, Set, Map, RegExp, String, Number and JSON methods;
- canonical record outputs retained `Object.prototype`, allowing optional fields to appear later after prototype pollution.

## Goal

Preserve XP-001 schema and accepted canonical data while making Pack parsing/canonicalization fail closed and independent from post-initialization prototype mutation.

```text
unknown Pack input
      ↓
canonical Experience Pack parser
      ↓
own-data snapshots + bounded logical arrays
      ↓
existing Pack semantic validation
      ↓
null-prototype canonical records + dense canonical arrays
      ↓
deep-frozen ExperiencePackManifest
      ↓
deterministic serialization through captured intrinsics
```

## Hardening

1. Plain object semantics are read only from null-prototype own-data snapshots.
2. Accessor and symbol-backed record state fails closed without executing getters.
3. Array-valued fields snapshot the own `length` data descriptor once, enforce caller limits before traversal/allocation, and require each semantic index to be an own data property.
4. Named/symbol array metadata is non-semantic and is never enumerated or executed.
5. Canonical array writes use own data descriptors rather than inherited `.push()` behavior.
6. Security-critical parser/canonicalization operations use module-captured intrinsics or own-index loops rather than mutable ambient Array/Object/Set/Map/RegExp/String/Number/JSON prototype dispatch.
7. Canonical manifest, publisher, metadata, compatibility and artifact records are null-prototype own-data snapshots; optional fields cannot later bleed in from `Object.prototype` pollution.
8. Runtime Pack arrays remain normal dense Arrays to preserve the public Pack array contract.
9. Deterministic field ordering and serialization remain stable.

## Explicit non-goals

Do not change Pack schema version, Pack identity/version/media-type grammar, accepted canonical Pack semantics, array public types, Registry/Marketplace semantics, transport/filesystem/network/signing/OCI behavior, or introduce a second parser.

## Security invariants

- missing required fields cannot be supplied through prototypes;
- optional canonical fields cannot appear later through prototype pollution;
- inherited getters/data cannot satisfy semantic validation;
- sparse array holes cannot read inherited numeric values;
- array subclasses/custom prototypes fail closed;
- collection work is bounded before traversal;
- parser-created canonical writes do not invoke inherited numeric setters;
- post-initialization mutation of tested ambient intrinsics cannot change Pack parsing or serialization semantics;
- arbitrary unknown Pack object fields remain rejected;
- output remains detached and deeply frozen;
- validation errors do not gain arbitrary secret/customer-content reflection surfaces.

## Acceptance

1. XP-001 contract behavior remains valid;
2. polluted object/array prototypes cannot supply semantic Pack state;
3. proxy length/accessor/key behavior is snapshotted or rejected fail closed;
4. oversized semantic arrays reject before semantic traversal;
5. canonical serialization is deterministic under tested ambient intrinsic poisoning;
6. canonical Pack records have null prototypes while canonical arrays preserve Array runtime behavior;
7. exact latest-main diff remains XP owner scope only;
8. exact reconciled-head hosted CI and adversarial review pass;
9. local repository CI remains deferred to the final all-phase integration gate per user instruction.
