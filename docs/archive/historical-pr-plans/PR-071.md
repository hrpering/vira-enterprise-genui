# PR-071: Telemetry Golden Gate

## Goal
Close the Telemetry MVP phase with a public-surface integration test proving the event contract, bounded channel lifecycle, and exporter port preserve privacy and deterministic cleanup together.

## Scope
- Add one golden integration suite using only public Telemetry exports.
- Prove caller-owned timestamps and canonical fields survive an immutable exporter snapshot.
- Prove non-contract prompt/user/domain-payload-shaped fields are rejected before exporter invocation.
- Prove provider exceptions are reduced to generic operation-level failure without secret leakage.
- Prove shutdown closes admission and calls flush before exporter shutdown.
- Document the Telemetry MVP boundary and explicitly defer provider/vendor concerns.

## Explicitly out of scope
- production instrumentation in other packages.
- OpenTelemetry/OTLP adapters.
- sampling, retry, backoff, persistence, or background batching.
- trace/span ID generation.
- hidden clocks.
- vendor exporters.

## Acceptance criteria
- golden tests exercise only the public `@vira-enterprise-genui/telemetry` surface.
- sensitive-shaped extra fields never reach exporter code.
- exported batches/events are immutable snapshots.
- provider exception text does not appear in channel results.
- shutdown ordering is deterministic and post-shutdown emission is denied.
- no production behavior changes in this PR.
- this PR is exactly one commit on top of PR-070.

## RE/QC focus
Look for privacy-surface widening, hidden data enrichment, provider exception leakage, mutable snapshots, hidden time/ID generation, post-shutdown admission, implicit retry, or test-only access to internal modules.
