# PR-005: DomainData Protocol v1

## Goal
Define the canonical boundary between raw enterprise/tool data and the semantic GenUI system.

## Scope
- Define versioned `DomainData` with semantic `domain` and `type` identifiers.
- Normalize `data` through the shared canonical JSON parser.
- Add minimal typed source metadata using semantic identifiers rather than opaque endpoint/token references.
- Add explicit Unix-millisecond freshness metadata and ordering validation.
- Reject unknown fields and accessor/non-canonical inputs.
- Add a semantic domain-data key, golden fixture, contract tests, and documentation.

## Out of scope
- Calling external tools or customer APIs.
- Tool-bridge provider implementations.
- Domain-specific schemas such as flights/products/accounts.
- Capability, ExperiencePlan, Patch, planner, or rendering behavior.
- Endpoint/auth/session storage.
- Cache invalidation or automatic freshness behavior.

## Allowed files
- `packages/protocol/src/domain-data/**`
- `packages/protocol/src/index.ts`
- `tests/contract/domain-data.test.ts`
- `tests/fixtures/protocol/domain-data.v1.json`
- `docs/protocol/domain-data.md`
- `docs/pr-plans/PR-005.md`

## Acceptance criteria
- A valid fixture parses, clones, and canonical JSON round-trips.
- Raw/non-canonical data is rejected without intentionally invoking accessors on normal objects.
- Domain/type use the same shared identifier grammar as Intent.
- Source metadata cannot carry opaque endpoint/token references through a generic `ref` field.
- Source metadata cannot smuggle unknown fields into the canonical envelope.
- Freshness uses safe non-negative integer Unix milliseconds and validates expiry ordering.
- Freshness metadata does not execute cache/fetch behavior.
- No provider SDK, endpoint, credential, UI, or renderer concept enters the contract.
- Protocol code performs no filesystem/network access.

## RE/QC focus
Confirm DomainData is a normalization boundary rather than a permissive raw-response bag. Inspect source/freshness metadata for hidden provider coupling, raw secrets, executable values, time-unit ambiguity, lossy JSON behavior, cache/business logic, and renderer leakage.
