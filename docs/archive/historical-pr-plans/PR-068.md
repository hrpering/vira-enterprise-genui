# PR-068: Telemetry Exporter Port

## Goal
Add the minimal trusted provider/export lifecycle boundary without coupling canonical telemetry events to OpenTelemetry or a vendor SDK.

## Scope
- Add `TelemetryExporterPort` with required `exportBatch`, `flush`, and `shutdown` operations.
- Snapshot required provider data methods without executing them during configuration.
- Support class/prototype methods while preserving provider instance state as `this`.
- Ignore provider return payloads.
- Normalize all operations to asynchronous machine results.
- Convert provider throws/rejections to generic `PROVIDER_FAILURE` without raw error text.
- Reject missing/non-callable/getter-backed required methods without invoking getters.
- Keep the port immutable.
- Add contract tests and documentation.

## Explicitly out of scope
- event validation inside the port.
- queueing or batch construction.
- retry/backoff.
- network transport implementation.
- idempotent lifecycle state.
- exporter concurrency policy.
- provider-specific error details.
- OpenTelemetry/OTLP/vendor dependencies.

## Acceptance criteria
- creation invokes no provider method.
- class instances work.
- trusted method references are snapshotted while `this` state remains live.
- provider return values do not escape.
- sync throws and async rejections produce only generic machine failure results.
- getter-backed methods are rejected without getter execution.
- all three lifecycle methods are mandatory.
- port object is frozen.
- Telemetry package remains dependency-free.

## RE/QC focus
Look for provider invocation during configuration, method replacement following, lost `this`, raw provider errors or return payloads, getter execution, missing lifecycle methods, event/schema coupling, queue/retry behavior, provider-specific dependencies, or mutable port state.
