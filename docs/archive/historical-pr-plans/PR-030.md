# PR-030: Experience Recipe Contract

## Goal
Define a deterministic protocol-only planning blueprint that maps one canonical intent identity to required state and semantic capability configuration.

## Scope
- Add versioned ExperienceRecipe contract.
- Validate exact canonical intent identity.
- Validate ordered unique required-state fields.
- Validate optional blocker-field -> Capability mappings.
- Require mapped fields to belong to requiredState.
- Validate available/future capabilities and global capability uniqueness/limits.
- Add exact `matchRecipeIntent` helper.
- Return frozen serializable outputs.

## Out of scope
- Candidate/user state values.
- Planner execution.
- Layout/disclosure policy.
- Component/brand mapping.
- Runtime actions/permissions.
- LLM/model/fuzzy routing.
- Network/tool execution.

## Acceptance criteria
- Recipe selection is exact and deterministic.
- Confidence/parameters do not affect recipe selection.
- Protocol owns semantic identifier/Capability/Intent validation primitives.
- Capability identity is unambiguous across recipe positions.
- Recipe cannot become a layout/component/action/execution bag.
- Caller-owned input is not retained mutably.

## RE/QC focus
Look for hidden inference, fuzzy matching, capability-position ambiguity, state-field mismatch, planner/composer dependency inversion, layout/component/action leakage, mutable outputs, or resource-limit gaps.
