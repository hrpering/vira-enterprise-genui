# PR-062: Exact Capability Allowlist

## Goal
Add a deny-by-default, exact-membership capability gate without duplicating Protocol capability grammar or introducing wildcard/role/prefix authorization behavior.

## Scope
- Add versioned `CapabilityAllowlistPolicy`.
- Allow an explicit bounded list of opaque capability keys.
- Add `evaluateCapabilityAllowlist(policy, capabilityKey)` returning `allow | deny`.
- Use exact, case-sensitive membership only.
- Permit an empty allowlist as an intentional deny-all policy.
- Reject duplicate entries, sparse/accessor-backed arrays, custom/symbol properties, oversized policy lists, and unknown policy fields.
- Keep Security dependency-free and leave semantic capability validation to Protocol/upstream owners.
- Add tests and documentation.

## Explicitly out of scope
- Protocol capability parsing/grammar.
- wildcard/glob/regex/prefix matching.
- roles, claims, tenant policy, or permission inheritance.
- action authorization.
- component selection.
- network policy.

## Acceptance criteria
- Security has no dependency on Protocol and does not copy Protocol's semantic ID regex.
- exact configured key matches allow; every other bounded key denies.
- case changes do not match.
- empty policy denies every valid candidate key.
- no fallback, wildcard, fuzzy match, or namespace prefix semantics exist.
- symbol/custom policy properties fail closed rather than becoming ignored configuration.
- malformed policy fails before a decision is returned.
- returned decision objects are immutable.

## RE/QC focus
Look for duplicated semantic-ID grammar, wildcard/prefix matching, implicit allow defaults, ignored custom/symbol configuration, role/claim coupling, mutation of policy inputs, accessor execution, capability execution, or Security importing Protocol/Runtime Web.
