# PR-012: Runtime patch engine

## Goal
Apply validated Patch Protocol operations to the current ExperiencePlan without mutating RuntimeState or allowing patches to rewrite runtime identity/revision fields.

## Scope
- Validate incoming patches through Protocol.
- Treat `RuntimeState.plan` as the patch document; `experienceId` and `revision` are never addressable by patch paths.
- Apply operations in source order to a private normalized plan clone.
- Implement deterministic `set`, `remove`, `merge`, `append`, and `replace` semantics.
- Require intermediate paths/targets to exist; never auto-create intermediate containers.
- Revalidate the final document through `parseExperiencePlan` before publishing a new RuntimeState.
- Increment revision exactly once for a successful non-empty patch; empty patches return the original state unchanged.
- Freeze the resulting plan/state.
- Add contract tests and documentation.

## Out of scope
- Permission checks/authorization.
- Runtime reducer/action dispatch.
- Lifecycle transitions.
- Host/backend effects.
- DOM rendering or diffing.
- Network synchronization/message queues.

## Allowed files
- `packages/runtime-core/src/patches/**`
- `packages/runtime-core/src/index.ts`
- `tests/contract/runtime-patch-engine.test.ts`
- `docs/runtime-core/patches.md`
- `docs/pr-plans/PR-012.md`

## Acceptance criteria
- Original RuntimeState and nested plan/state are never mutated.
- Patch paths address ExperiencePlan root (`/state/...`, `/capabilities/...`, etc.), never RuntimeState root.
- Operations execute deterministically in source order.
- Array writes never create holes; `append` is the only append semantic.
- Missing paths and target-type mismatches fail deterministically.
- A patch whose resulting document is not a valid ExperiencePlan is rejected atomically with no published partial state.
- Successful non-empty patches increment revision by one; empty patches preserve object identity/revision.
- No permission assumptions, side effects, network, DOM, or hidden globals exist.

## RE/QC focus
Look for mutation of the input state, prototype pollution, path traversal ambiguity, partial-state publication, revision bugs, unvalidated final documents, auto-created intermediate paths, permission bypass assumptions, hidden side effects, or patches reaching `experienceId`/`revision`.
