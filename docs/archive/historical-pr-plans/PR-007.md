# PR-007: ExperiencePlan Protocol v1

## Goal
Define the minimal semantic plan contract produced by planning before composition or rendering exists.

## Scope
- Define versioned `ExperiencePlan` with an opaque plan id, canonical Intent, resolved task state, and planned capability buckets.
- Model capability planning as `required`, `available`, and `future` semantic buckets.
- Normalize nested state and contracts without retaining caller-owned objects.
- Reject duplicate capability IDs across buckets.
- Reject unknown/presentational/executable fields.
- Add runtime parsing, a golden fixture, contract tests, and documentation.

## Out of scope
- Semantic regions or layout policy (composer responsibility).
- Canonical runtime actions or permissions (runtime-core responsibility).
- Data bindings, component props, renderer metadata, or brand tokens.
- Raw DomainData/tool payload storage inside the plan.
- Planner implementation or inference.

## Allowed files
- `packages/protocol/src/experience-plan/**`
- `packages/protocol/src/index.ts`
- `tests/contract/experience-plan.test.ts`
- `tests/fixtures/protocol/experience-plan.v1.json`
- `docs/protocol/experience-plan.md`
- `docs/pr-plans/PR-007.md`

## Acceptance criteria
- A valid plan parses, normalizes, and canonical JSON round-trips.
- Nested Intent and Capability contracts are validated through their owning parsers.
- Resolved state accepts canonical JSON objects only and is cloned during normalization.
- Missing capability buckets normalize to empty arrays.
- Duplicate capability IDs across any buckets are rejected.
- Unknown fields such as `regions`, `actions`, `layout`, `component`, and `policies` are rejected in v1.
- No DOM, React, CSS, endpoint, tool invocation, or customer-specific execution detail enters the plan contract.

## RE/QC focus
Confirm ExperiencePlan is a semantic planning artifact rather than a generic UI schema. Look for premature composer/runtime ownership, raw tool-data leakage, ambiguous capability classification, duplicated validation rules, caller-object retention, and executable/presentational fields.
