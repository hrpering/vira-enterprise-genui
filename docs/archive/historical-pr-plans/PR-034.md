# PR-034: Policy Adapter Contract

## Goal
Map validated Experience Recipes to semantic composition-policy references without duplicating Composer policies or introducing authorization semantics.

## Scope
- Add versioned PolicyAdapterContract.
- Map exact recipe IDs to layout/disclosure policy references.
- Require namespaced semantic policy references.
- Reject duplicate recipe mappings.
- Add `resolvePolicyRefsForRecipe` using ExperienceRecipe validation.
- Fail closed for unmapped recipes.
- Return frozen serializable policy references.

## Out of scope
- Runtime authorization/permissions.
- Security/network policy.
- Actual LayoutPolicy/DisclosurePolicy values.
- CSS/layout geometry.
- Role/claim evaluation.
- Callbacks or policy execution.

## Acceptance criteria
- Policy adapter cannot be confused with authorization.
- No default/fallback policy mapping exists.
- Adapter SDK does not import Composer or Runtime Core.
- Actual policy contents remain owner-layer concerns.
- Recipe input is validated by the Adapter SDK recipe owner.
- Outputs are immutable and serializable.

## RE/QC focus
Look for authorization confusion, duplicated Composer policy values, raw layout/disclosure values, fallback defaults, role/claim/network leakage, callbacks/execution, mutable refs, or dependency inversion.
