# PR-026: Composition Validation

## Goal
Create strict shape and source-plan integrity validation for ComposedExperience so downstream Runtime Web / SDK code never trusts TypeScript-only or detached composition data.

## Scope
- Export ExperiencePlan ID validation from Protocol owner.
- Export immutable composition-priority modes + validator from Planner owner.
- Parse/normalize ComposedExperience root fields.
- Delegate layout/disclosure/region validation to owning Composer contracts.
- Enforce minimal semantic mode/region consistency.
- Add source-plan integrity validation for plan ID, mode, and capability identity/order.
- Clone/freeze output and reject forged/accessor-backed inputs.

## Out of scope
- Domain-specific mode/layout compatibility.
- Component/brand selection.
- Runtime state/actions/permissions.
- DOM/CSS/responsive geometry.
- Network/model/tool behavior.

## Acceptance criteria
- Composer does not duplicate plan-ID regex or Planner mode strings.
- Engine output parses and validates against its source plan.
- Shape-valid capability injection/omission/reclassification fails integrity validation.
- Forged IDs/modes fail closed.
- resolve/interact require primary; settled forbids primary/supporting.
- Nested policy/region failures preserve public paths.
- Caller-owned nested values are not retained mutably.
- Output is frozen/serializable.

## RE/QC focus
Look for duplicated owner truth, TypeScript-only trust, detached artifact capability injection, mode/region contradictions, path-remap bugs, mutable references, policy validation bypass, layout/domain overreach, component/runtime leakage, or public parser fail-open behavior.
