# PR-045: Runtime Web Golden Integration Gate

## Goal
Close the framework-neutral Runtime Web core phase with one deterministic end-to-end integration suite across render preparation, mount environment, user events, Runtime Core state binding, and disposal without adding product behavior.

## Scope
- Add a deterministic travel experience integration fixture in test code.
- Exercise source-plan composition integrity and exact component mapping through mount.
- Exercise mandatory AccessibilityPolicy and container ResponsivePolicy through DOM begin context.
- Exercise transactional mount order and disposal through a fake trusted DOM Port.
- Exercise State Binding Session with allowed host action, allowed Runtime Core patch, confirm-gated action, and denied action.
- Assert effects remain data-only and semantic state changes only through Runtime Core revision advancement.
- Add fail-closed checks for forged composition and invalid UI event.

## Out of scope
- new Runtime Web production APIs.
- concrete browser DOM implementation.
- effect execution.
- network/tool calls.
- component implementations.
- Web SDK/Web Component/React wrappers.

## Acceptance criteria
- PR changes tests/docs only.
- One source ExperiencePlan drives composition, mount, and RuntimeState initialization.
- Mount receives expected accessibility policy + container band and commits only after ordered component mounts.
- Host-action and confirmation effects do not mutate state.
- Runtime patch advances revision exactly once and becomes the session current state.
- Denied/invalid events leave current state untouched.
- Forged composition fails before DOM Port access.
- Disposal is idempotent and reverse-ordered.

## RE/QC focus
Look for production-code changes hidden in the gate, duplicated task state, effect execution, integrity bypass, responsive/accessibility bypass, state advancement on confirm/deny, non-deterministic IDs/timing, or tests that merely mirror implementation without locking architecture boundaries.
