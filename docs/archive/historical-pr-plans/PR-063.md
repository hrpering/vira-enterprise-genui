# PR-063: Deny-by-Default Network Policy

## Goal
Add a pure, deny-by-default outbound network decision gate so Runtime Web/host integrations can authorize exact HTTPS origins and methods without Security performing network I/O.

## Scope
- Add versioned `NetworkPolicy` with bounded exact origin rules.
- Permit credential-free HTTPS origins only.
- Require an explicit non-empty bounded method set per configured origin.
- Add `evaluateNetworkRequest(policy, request)` returning allow/deny + reason.
- Canonicalize origins through the platform URL parser.
- Reject duplicate normalized origins and duplicate methods.
- Reject wildcard/custom/symbol/accessor-backed policy state.
- Permit an empty rule list as explicit deny-all.
- Accept request paths/query strings only after their exact origin is authorized.
- Reject URL fragments and embedded credentials.
- Add tests and documentation.

## Explicitly out of scope
- performing `fetch`, XHR, WebSocket, DNS, or socket operations.
- wildcard/subdomain/suffix matching.
- HTTP/non-TLS origins.
- redirects or redirect-chain verification.
- DNS rebinding/private-network analysis.
- per-path endpoint allowlists.
- headers/body inspection.

## Acceptance criteria
- Security remains dependency-free.
- empty policy denies all valid HTTPS requests.
- exact normalized origin + configured method allows.
- same origin + unconfigured method denies.
- another subdomain/port/origin denies.
- userinfo, HTTP, fragment-bearing, wildcard, malformed, accessor/custom policy inputs fail closed.
- method arrays are resource-bounded before iteration.
- decision evaluation performs no network activity.
- returned policy/request/decision values are immutable.

## RE/QC focus
Look for actual network calls, wildcard/suffix matching, implicit same-origin allow, redirect assumptions, HTTP fallback, credential acceptance, URL-string prefix matching, unbounded arrays, mutable policy state, ignored custom properties, or hidden DNS/host resolution.
