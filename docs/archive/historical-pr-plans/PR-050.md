# PR-050: Public Web SDK Host Patch API

## Goal
Expose a host-originated patch path that reuses Protocol validation, Runtime Core permission/reducer ownership, and the State Binding Session revision gate without pretending host updates are user events.

## Scope
- Add `StateBindingSession.processHostPatch(patch)`.
- Validate Patch through Protocol before action-ID allocation.
- Construct `runtime.patch.apply` with fixed `source: "host"` inside Runtime Web.
- Route the host RuntimeAction through Runtime Core `reduceRuntime` and the same session revision/invariant gate used by user events.
- Generalize the bound reduction value to `BoundRuntimeAction` while retaining `BoundUserEvent` as a compatibility alias.
- Preserve direct caller patch error paths (`$.operations...`) rather than inventing an outer `$.patch` object.
- Add public `sdk.patch(patch)`.
- Publish canonical action/effect/statechange/error notifications through the existing SDK subscription surface.
- Reject patch calls while listener notification is active before action-ID allocation.
- Add tests and documentation.

## Out of scope
- permission bypass for host actions.
- direct RuntimeState mutation.
- automatic DOM rerendering.
- effect execution.
- patch generation/diffing.
- network/tool/model calls.
- async queues.

## Acceptance criteria
- Invalid Patch fails before ID allocation and reports the Protocol path relative to the patch input.
- Successful patch action always has `type: "runtime.patch.apply"` and `source: "host"`.
- Runtime Core remains the sole permission/reducer owner.
- Allow advances revision exactly once through the existing session gate.
- Deny leaves state unchanged; confirm returns a data-only confirmation effect with unchanged state.
- Reentrant patch during SDK notification fails before ID allocation.
- SDK subscriptions observe results but never execute effects.
- Shared session reduction output is not semantically mislabeled as user-only.

## RE/QC focus
Look for host permission bypass, user-source spoofing, patch parsing after ID allocation, misleading error paths, user-only naming on host results, direct state mutation, duplicated revision logic, effect execution, reentrant revision interleaving, raw patch data bypassing Protocol validation, or hidden queues.
