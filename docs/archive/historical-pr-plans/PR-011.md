# PR-011: Canonical runtime actions

## Goal
Define the framework-neutral action data model that runtime-core can receive before reducers, permissions, or host execution exist.

## Scope
- Define immutable `RuntimeAction` with caller-supplied id, semantic type, semantic source, and canonical object payload.
- Normalize action input through Protocol canonical JSON parsing.
- Reuse shared semantic identifier validation for action types.
- Default omitted payload to an empty object.
- Reject DOM/backend/component/timestamp fields outside the canonical model.
- Require callers to supply action IDs; runtime-core does not generate random IDs or timestamps.
- Define action `source` as descriptive provenance only, never authorization evidence.
- Move the now-shared deep-freeze helper from the state folder into runtime-core internal utilities so actions do not depend on state implementation details.
- Add contract tests and documentation.

## Out of scope
- Dispatch/reducer behavior.
- Permission checks.
- Host/backend execution.
- DOM event mapping.
- Action effects or retries.
- Telemetry timestamps.

## Allowed files
- `packages/runtime-core/src/actions/**`
- `packages/runtime-core/src/internal/deep-freeze.ts`
- `packages/runtime-core/src/state/create.ts`
- `packages/runtime-core/src/state/freeze.ts` (removal)
- `packages/runtime-core/src/index.ts`
- `tests/contract/runtime-action.test.ts`
- `docs/runtime-core/actions.md`
- `docs/pr-plans/PR-011.md`

## Acceptance criteria
- Valid canonical actions normalize, clone, freeze, and JSON round-trip.
- Action type uses semantic namespace grammar.
- Source is limited to `user`, `host`, or `system` and is explicitly non-authoritative.
- Payload is a canonical JSON object; missing payload normalizes to `{}`.
- Unknown implementation fields such as DOM event names, endpoints, component names, callbacks, and timestamps are rejected.
- Action logic does not import state submodule internals; generic shared immutability utility lives under runtime-core internal.
- No random ID, clock access, network access, DOM, React, backend invocation, or permission grant exists.

## RE/QC focus
Look for DOM-event leakage, endpoint/execution coupling, nondeterministic ID/timestamp generation, mutable payload references, generic executable bags, duplicated semantic-id rules, state/action hidden coupling, source-based privilege assumptions, or permission logic appearing early.
