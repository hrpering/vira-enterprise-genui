# PR-004: Intent Protocol v1

## Goal
Implement the first versioned canonical product contract: semantic intent.

## Scope
- Add reusable canonical JSON value types and strict runtime parsing required by intent parameters.
- Add one internal accessor-safe plain-object input primitive for reuse by later protocol parsers.
- Add shared semantic identifier primitives so future protocol contracts reuse the same namespace/segment grammar.
- Define versioned `Intent` types.
- Parse/normalize unknown input into canonical Intent v1 without intentionally invoking accessor properties.
- Bound canonical JSON nesting to prevent unbounded recursive parsing.
- Reject unknown top-level intent fields and invalid semantic identifiers.
- Validate optional confidence and parameters.
- Expose a deterministic semantic intent key.
- Add a golden fixture, contract tests, and protocol documentation.

## Out of scope
- DomainData, Capability, ExperiencePlan, or Patch contracts.
- Intent inference or LLM calls.
- Mapping a customer's intent taxonomy into canonical intent.
- UI/component selection.
- Runtime state or action handling.

## Acceptance criteria
- A valid v1 fixture parses and JSON round-trips canonically.
- Unsupported versions fail with a typed validation issue.
- Invalid namespace/name/confidence values fail deterministically.
- Empty/trailing-hyphen semantic identifier segments are rejected.
- Shared semantic identifier rules are reusable by later protocol contracts rather than duplicated.
- Shared object input reading rejects accessors without invoking getters on normal objects.
- Unknown top-level fields are rejected.
- Intent parameters accept canonical JSON objects only and are cloned during normalization.
- Excessively deep canonical JSON fails with a validation issue rather than relying on stack overflow behavior.
- No DOM, React, CSS, endpoint, tool, customer, or renderer concepts enter the intent contract.
- Protocol code performs no network or filesystem access.

## RE/QC focus
Confirm intent is semantic rather than presentational or executable. Inspect runtime parsing for lossy JSON behavior, accessor side effects, unbounded nesting, unsafe object assumptions, hidden customer/domain coupling, duplicated identifier grammar, and accidental framework leakage.
