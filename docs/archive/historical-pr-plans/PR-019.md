# PR-019: Experience Planner

## Goal
Compose the deterministic State Resolver and Capability Resolver into canonical ExperiencePlan creation without inference, presentation ownership, or execution behavior.

## Scope
- Validate explicit Intent through Protocol.
- Resolve current/required/candidate state through State Resolver.
- Resolve blockers through Capability Resolver.
- Build and revalidate the final ExperiencePlan through Protocol.
- Keep plan ID caller-supplied and deterministic.
- Freeze final canonical plan data.
- Add integration-style contract tests and documentation.

## Out of scope
- LLM/model planning.
- DomainData/tool normalization.
- Composition regions/layout/disclosure.
- Runtime actions/permissions/effects.
- Component/brand mapping.
- Network/DOM/framework behavior.

## Acceptance criteria
- Valid inputs deterministically produce a Protocol-valid ExperiencePlan.
- Candidate state fills only missing fields; conflicts retain current state and require explicit capabilities.
- Unmapped blockers fail closed.
- Invalid Intent and invalid final plan shapes are rejected through owning Protocol parsers.
- Plan IDs are never generated implicitly.
- Output is recursively frozen and caller inputs are not retained.
- No presentation/execution/framework/customer behavior enters the plan.

## RE/QC focus
Look for hidden inference, duplicated Protocol validation, generated IDs/timestamps, presentation/action leakage, conflict auto-resolution, raw DomainData/tool interpretation, mutable output, error-path misattribution, hidden network/model calls, or planner ownership crossing into composer/runtime.
