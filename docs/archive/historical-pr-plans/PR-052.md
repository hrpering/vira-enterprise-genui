# PR-052: `<vira-experience>` Event Surface

## Goal
Expose user/host operations and canonical Runtime Web notifications through the Web Component without duplicating reducer/effect behavior.

## Scope
- Add imperative `dispatch(event)` and `patch(patch)` methods that delegate to the configured Runtime Web SDK.
- Bridge SDK `action`, `effect`, `statechange`, and `error` notifications to standards-native CustomEvents.
- Use canonical event names: `vira-action`, `vira-effect`, `vira-statechange`, `vira-error`.
- Emit events synchronously with `bubbles: true`, `composed: true`, and `cancelable: false`.
- Keep canonical SDK payloads as event `detail` without reinterpretation.
- Preserve Runtime Web reentrancy guards when native event listeners call back into the element.
- Allow injected CustomEvent factory for tests/non-browser hosts; injected registration platforms must provide that factory explicitly.
- Browser global is resolved only when the default browser platform/event factory is used.
- Add tests and documentation.

## Out of scope
- automatic effect execution.
- event cancellation as authorization.
- JSON attributes.
- DOM rerendering.
- async/event queues.
- React wrapper.

## Acceptance criteria
- Web Component dispatch/patch do not create RuntimeActions themselves.
- user dispatch remains `source: user`; host patch remains `source: host` through Runtime Web ownership.
- native event `detail` equals the canonical SDK notification payload.
- effect CustomEvents are notifications only.
- native event listener reentrant patch/dispatch remains rejected by Runtime Web before extra ID allocation.
- event factory/listener exceptions cannot change reducer/state results.
- an injected custom-element registration platform cannot become partially functional because its event factory was lost.
- package dependency direction remains web-component -> runtime-web only.

## RE/QC focus
Look for action construction in web-component, effect execution, privilege/source spoofing, cancellation-based permission logic, async queues, payload rewriting, lost injected event factories, global CustomEvent access at module load, reentrant state drift, or direct runtime-core imports.
