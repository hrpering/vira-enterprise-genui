# PR-070: Component Security Reconciliation Gate

## Goal
Reconcile the previously implemented exact component allowlist and Runtime Web component authorization gate into the canonical MVP chain without regressing CSP, network policy, or Telemetry work that continued on the parallel security branch.

## Why this PR exists
The component-security work and the CSP/security-golden work diverged from the same capability-security ancestor. Telemetry continued from the CSP branch, so the component gate was never present in the canonical head. This PR closes that fork explicitly instead of merging the stale branch wholesale.

## Scope
- Carry the exact component allowlist primitive into the current `@vira-enterprise-genui/security` package.
- Export both component authorization and the existing CSP/network/capability primitives from Security.
- Require and snapshot `componentAllowlist` in Runtime Web configuration alongside `capabilityAllowlist`.
- Authorize every resolved component binding before Runtime Web performs DOM measurement, lifecycle begin, or mount work.
- Preserve explicit `INVALID_COMPONENT_ALLOWLIST` and `COMPONENT_DENIED` fail-closed outcomes.
- Restore component-security contract coverage and update existing Runtime Web / Web Component / React fixtures to provide explicit component policies.
- Preserve all current CSP, network-policy, Security golden-gate, and Telemetry files by building this change directly on PR-069.

## Explicitly out of scope
- changing the component vocabulary.
- wildcard component matching.
- deriving component permission from capability permission.
- merging the stale security branch wholesale.
- modifying CSP or network policy semantics.
- modifying Telemetry behavior.
- adding dynamic code, arbitrary HTML, iframe, or custom JavaScript execution.

## Acceptance criteria
- Security publicly exports capability, component, network, CSP, and content guards together.
- Runtime Web configuration requires both capability and component allowlists.
- component mappings or adapter registrations never imply authorization.
- denied or invalid component policy prevents DOM host calls and runtime mount work.
- all wrappers/golden fixtures use explicit component policy rather than hidden defaults.
- canonical CSP/network/Telemetry tree remains present and unchanged outside this reconciliation diff.
- this PR is exactly one commit on top of PR-069.

## RE/QC focus
Look for authorization bypass via mapping, casing, duplicate policies, getter-backed input, configuration mutation, DOM work before deny, accidental replacement of CSP/network exports, or stale-branch files that would roll back newer canonical work.
