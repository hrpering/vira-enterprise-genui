# PR-017: Planner State Resolver

## Goal
Add a deterministic state-resolution primitive that identifies known, missing, and conflicting task fields without inference or silent overwrite.

## Scope
- Normalize canonical state, ordered required field names, and optional explicit candidate values.
- Use top-level semantic state fields for v1.
- Preserve current state when an explicit candidate conflicts.
- Fill only missing required fields from explicit candidates.
- Return immutable `state`, `known`, `missing`, and `conflicts` data.
- Bound requirement/candidate field counts before recursive canonical parsing.
- Add planner package export/dependency surface, tests, and documentation.

## Out of scope
- LLM/model inference.
- Domain-specific extraction or API/tool interpretation.
- Nested path mutation.
- Capability resolution.
- ExperiencePlan creation.
- Runtime lifecycle/permissions/actions.
- DOM/framework/network behavior.

## Acceptance criteria
- Same canonical input produces the same result.
- Existing state is never silently overwritten by a different candidate.
- Candidate-only required fields are cloned into resolved state.
- Missing required fields are explicit.
- Structurally equal JSON objects do not produce false conflicts due to key order.
- Duplicate/invalid requirements and unrequested candidates are rejected.
- Oversized requirement/candidate metadata is rejected before recursive parsing.
- Caller-owned input is not retained or mutated.
- No domain/customer/framework/runtime behavior leaks into the resolver.

## RE/QC focus
Look for hidden inference, conflict auto-resolution, generic path mutation, state mutation, candidate provenance assumptions, domain coupling, raw tool/LLM payload handling, mutable outputs, duplicated runtime patch behavior, resource-limit gaps, or nondeterministic ordering.
