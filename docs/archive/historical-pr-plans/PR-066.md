# PR-066: Security Golden Gate

## Goal
Lock the Security package's MVP invariants together through public APIs without adding production behavior.

## Scope
- Add one deterministic integration test covering PlainTextContent, capability allowlisting, NetworkPolicy, and CSP host requirements.
- Prove markup-looking strings remain plain text and HTML sink authorization remains unavailable.
- Prove capability membership is exact rather than fuzzy/prefix based.
- Prove network authorization remains exact origin + method and wildcard request hosts fail closed.
- Derive CSP connect requirements from the same validated NetworkPolicy while keeping method enforcement in NetworkPolicy.
- Prove normalized network/CSP outputs do not follow caller mutation.
- Document the cross-control ownership model.

## Explicitly out of scope
- new Security production APIs.
- Runtime Web behavior changes.
- CSP header middleware.
- network execution.
- HTML sanitization/HTML sink enablement.
- role/claim/tenant authorization.

## Acceptance criteria
- production source changes = 0.
- golden test imports public Security package APIs only.
- markup-looking text is preserved as text, not parsed or stripped.
- unsupported HTML sink remains denied.
- exact capability allow/near-match deny is locked.
- exact origin+method network decision is locked.
- wildcard/percent-decoded wildcard request host remains invalid.
- CSP connect requirement reflects normalized network origin without absorbing method authorization.
- caller mutation cannot alter normalized network/CSP output.

## RE/QC focus
Look for tests reaching internal modules, production source changes, duplicated implementation logic in tests, weakened assertions, hidden HTML enablement, fuzzy authorization, wildcard regression, CSP/network conflation, or mutation leakage.
