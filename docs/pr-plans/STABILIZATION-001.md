# STABILIZATION-001: Reverse-Engineering Ship Gates

## Goal
Close the release-engineering and Studio integration gaps found during whole-repository reverse-engineering/QC without widening the Vira product boundary or adding product features.

## Reverse-engineering findings
- Runtime, Protocol, Planner, Composer, permission, publication, tool, telemetry and CSP boundaries are structurally fail-closed and must remain unchanged in semantics.
- The Experience Studio React workbench bypasses the installed Puck type surface by re-declaring Puck props behind `unknown` casts. This allowed a Puck 0.23-only DnD surface to remain in code after pinning Puck to 0.22.4.
- Existing Studio integration tests validate canonical authoring/reconciliation/publish behavior but never mount the React/Puck workbench in a browser, so a browser-only white-screen regression can escape the suite.
- Root verification does not execute the Pegasus chat demo typecheck/build gate.
- Package-boundary configuration grants Planner and Composer dependencies that their current contracts do not require.
- Canonical JSON parsing bounds nesting depth but not total node count, container width, or string size.
- GitHub Actions is configured but hosted jobs currently fail before any step is allocated (`runner_id=0`, empty step list). This is an external execution blocker, not evidence that repository commands fail.
- `main` currently has no enforced branch protection/required checks. The available repository connector exposes this state for reading but not an administrative protection write.
- No committed `pnpm-lock.yaml` exists. A lockfile must be generated by pnpm from the real workspace dependency graph; it must not be fabricated by static editing.

## Scope
- Remove the version-incompatible Puck DnD surface and make the installed Puck component itself own compile-time prop validation.
- Keep Vira's custom Layers panel and canonical `StudioDocument`/`StudioPublication` model unchanged.
- Add stable Vira-owned browser test hooks and a Chromium Playwright smoke test that mounts the real Experience Studio workbench, switches its main panels, publishes, and fails on uncaught page errors.
- Add the Pegasus chat typecheck/build to the root verification gate.
- Add a separate browser verification command and wire CI to install Chromium and execute it after repository verification.
- Pin third-party GitHub Actions to the commit SHAs currently referenced by their v6 tags.
- Tighten Planner and Composer package-boundary allowlists to the dependencies their package manifests actually declare.
- Add conservative canonical JSON resource budgets for total nodes, array width, object width, single-string length and aggregate string length, with contract tests.

## Out of scope
- New Studio features, new Puck APIs, arbitrary HTML/JavaScript, new network execution, message queues, model/provider behavior, or business APIs.
- Changing Runtime Core authorization/action semantics.
- Publishing private workspace packages to npm or defining commercial release/versioning policy.
- Mass-closing historical PRs or deleting branches in the same code change.
- Fabricating a pnpm lockfile without running pnpm.
- Claiming GitHub Actions verification while the hosted runner has not executed steps.

## Acceptance criteria
- `packages/studio-workbench-react` no longer re-declares a synthetic Puck runtime prop contract and no longer passes Puck 0.23 DnD options while pinned to Puck 0.22.4.
- TypeScript sees the real `Puck` component at the render call so unsupported future props fail compilation instead of passing through an `unknown` cast.
- Studio browser smoke covers initial render, Components, Layers, Views, Data and Actions panels, Properties visibility, Publish, and uncaught browser errors.
- `pnpm verify` includes Pegasus chat typecheck/build.
- `pnpm verify:browser` is the explicit real-browser Studio gate; CI installs Chromium before invoking it.
- Planner can depend only on Protocol; Composer can depend only on Protocol and Planner.
- Canonical JSON rejects inputs that exceed documented resource budgets before traversing unbounded wide payloads.
- Existing fail-closed permission, publication, binding, tool normalization, telemetry and CSP semantics are unchanged.

## Verification plan
1. `pnpm check:boundaries`
2. `pnpm lint`
3. `pnpm typecheck`
4. `pnpm test`
5. `pnpm build`
6. `pnpm build:experience-studio`
7. `pnpm demo:pegasus-chat:check`
8. Install Chromium once: `pnpm --filter @vira-enterprise-genui/experience-studio-demo exec playwright install chromium`
9. `pnpm verify:browser`

GitHub Actions output is classified separately from command verification until a runner actually starts and reports executed steps.

## Post-merge administrative gates
- Generate and commit `pnpm-lock.yaml` from a clean Node 24 / pnpm 11.24.0 workspace, then switch CI to `pnpm install --frozen-lockfile`.
- Enable `main` branch protection/ruleset with required verification once GitHub runner allocation is functional.
- Classify and close obsolete PRs/branches in a dedicated repository-hygiene pass.
- Define package build/export, semantic versioning, provenance, SBOM and release policy before external SDK distribution.
