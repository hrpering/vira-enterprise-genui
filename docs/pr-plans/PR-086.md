# PR-086: Human Experience Studio workbench

## Goal
Close the gap between the Studio authoring APIs and a real human-operated Puck workbench.

## Scope
- add an editor-neutral `studio-workbench` controller over view, binding, flow, preview and publish commands;
- add safe create/select/delete/set-entry screen commands without weakening Studio schema invariants;
- expose transient Puck-id to canonical Studio-node resolution for selected editor components;
- add `studio-workbench-react` with explicit Puck Components, Layers, Views, Data, Actions and Properties panels;
- wire Puck drag/drop/reorder to canonical reconciliation;
- wire Data selectors to approved binding-source commands;
- wire component events to approved action aliases and success/empty/error routes;
- wire the Puck publish button to the shared publication gate;
- remount from canonical state after non-Puck mutations or failed reconciliation.

## Boundaries
No endpoint editor, raw CSS/HTML/JS, arbitrary expressions, free-form workflow graph, persistence, auth or deploy ownership. Puck remains transient editor infrastructure; canonical behavior remains in Vira contracts.

## Acceptance
A human can compose a view visually, add/switch screens, bind data, bind actions/routes and produce a validated StudioPublication without calling authoring APIs manually.
