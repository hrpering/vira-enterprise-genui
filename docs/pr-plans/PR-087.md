# PR-087: Runnable human Studio demo and insertion safety

## Goal
Prove the audited human Experience Studio in a real browser surface and close the required-prop drag/drop gap discovered during reverse engineering.

## Scope
- add editor-only safe insertion defaults for required catalog props;
- keep defaults out of StudioDocument, Protocol and runtime contracts;
- add regression coverage for string/number/boolean/enum defaults;
- add `examples/experience-studio-demo` with Vite + React + Puck;
- exercise Components, Layers, Views, Data, Actions, Properties and Publish through the real Workbench;
- keep the demo launchable with the workspace filter command.

## Boundaries
- no backend/network execution;
- no raw HTML/CSS/JS authoring surface;
- no runtime dependency on Puck;
- no catalog schema expansion for editor bootstrap metadata;
- no persistence/auth/deploy ownership.

## Acceptance criteria
- newly dragged components with required primitive/enum props start from a canonical editable value;
- existing document values are not overwritten by insertion defaults;
- the demo starts from the workspace and renders the human workbench;
- publish still goes through the shared validation gate;
- repository verification remains the final release gate.
