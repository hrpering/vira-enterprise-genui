# PR-003: Shared deterministic test harness

## Goal
Establish framework-neutral test primitives before protocol/runtime behavior is introduced.

## Scope
- Typecheck test TypeScript alongside package/example source.
- Add Node type declarations matching the Node 24 toolchain used by typed test helpers.
- Add deterministic clock and sequence-ID helpers.
- Add a strict canonical JSON round-trip helper for future contract tests.
- Document fixture hygiene and test-boundary rules.
- Add self-tests for every shared helper.

## Out of scope
- Fake production adapters before adapter contracts exist.
- Protocol model implementation.
- Runtime/planner/composer behavior.
- Browser/E2E infrastructure.
- Network-backed tests.

## Allowed files
- `package.json`
- `tsconfig.json`
- `tests/README.md`
- `tests/fixtures/README.md`
- `tests/helpers/**`
- `docs/pr-plans/PR-003.md`

## Acceptance criteria
- Shared helpers are deterministic and do not read wall-clock time or randomness.
- Helpers have no dependency on browser APIs or production packages.
- TypeScript checks tests under strict project settings with Node 24 type declarations available.
- Canonical JSON checks reject lossy JSON inputs such as `undefined`, non-finite numbers, class instances, sparse arrays, circular references, and negative zero.
- Fixture policy explicitly rejects secrets, PII, raw customer payloads, and auth/session material.
- Test harness self-tests cover reset/advance/error behavior.

## RE/QC focus
Ensure this PR does not invent future production interfaces merely to make testing convenient. Confirm helpers are deterministic, side-effect-light, framework-neutral, and safe for reuse in protocol/runtime contract tests. Confirm the JSON helper rejects values that `JSON.stringify` would silently discard or coerce.
