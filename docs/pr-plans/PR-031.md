# PR-031: Component Adapter Contract

## Goal
Define an exact framework-neutral mapping from canonical Capability identities to semantic component references.

## Scope
- Add versioned ComponentAdapterContract.
- Validate bounded Capability -> component-reference mappings.
- Require namespaced semantic component references.
- Reject duplicate capability mappings.
- Add `resolveComponentForCapability` exact lookup.
- Reuse Protocol Capability validation and ExperiencePlan capability limits.
- Return frozen serializable outputs.

## Out of scope
- React/Vue/Web Component implementations.
- Module/import paths or URLs.
- HTML tags/templates/props.
- Rendering or DOM lifecycle.
- Runtime permissions/actions.
- Dynamic component loading.

## Acceptance criteria
- One capability has at most one mapping per contract.
- Unmapped capabilities fail closed.
- Component references are semantic identifiers, never executable/importable implementation values.
- Multiple capabilities may intentionally resolve to one component reference.
- Protocol remains owner of Capability validation and capability limits.
- Outputs are immutable and serializable.

## RE/QC focus
Look for executable component values, import/URL/tag leakage, props ownership, duplicate capability ambiguity, implicit fallback selection, runtime permission confusion, mutable output, or duplicated Capability grammar.
