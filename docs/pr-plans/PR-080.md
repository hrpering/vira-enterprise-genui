# PR-080: Studio preview and publish gate

## Goal
Separate mutable Studio drafts from validated immutable publications and give the Studio UI a safe view-scoped preview descriptor.

## Scope
- add `@vira-enterprise-genui/studio-publish`;
- validate component/binding source constraints before publishing;
- validate Action Adapter aliases and outcome flow before publishing;
- compile only validated documents through the existing Studio compiler;
- expose one view-scoped preview descriptor and dependency manifest;
- keep preview rendering implementations outside serializable artifacts;
- add Pegasus-style publish/deny coverage.

## Out of scope
- persistence, auth, approval workflow or deployment;
- hidden timestamps/revision IDs;
- network calls or runtime execution;
- component render functions in publication data;
- automatic publish from Puck onChange.

## Acceptance criteria
- invalid component/binding/action references cannot produce StudioPublication;
- preview and publish share the same validation gates;
- preview manifest is deterministic and view-scoped;
- publication remains the existing editor-neutral StudioPublication contract;
- no core/runtime behavior changes.
