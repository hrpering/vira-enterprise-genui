# PR-056: Tool Result → DomainData Normalization

## Goal
Map an already provider-neutral ExternalToolResult to canonical Protocol DomainData through an explicit exact tool→domain/type mapping, without arbitrary transforms or invented data.

## Scope
- Add versioned ToolDomainMapping contract.
- Map one exact semantic tool identity to one canonical DomainData domain/type.
- Normalize success/partial results into Protocol-validated DomainData.
- Preserve tool identity as DomainData source and preserve freshness metadata.
- Preserve optional semantic partial failure metadata outside DomainData.
- Return typed empty/failure outcomes without manufacturing `data: null` or fake DomainData.
- Fail closed on tool/mapping identity mismatch.
- Add shared Tool Bridge deep-freeze helper and keep normalized outputs immutable.
- Add tests and documentation.

## Out of scope
- payload selectors/transforms/default values.
- Adapter SDK authorization/membership checks.
- provider-specific parsing.
- retry/tool execution/network behavior.
- stale-time evaluation.

## Acceptance criteria
- Tool Bridge still depends internally only on Protocol.
- mapping contains semantic identity/domain/type only; transform/selector/default/component/provider fields fail closed.
- success/partial DomainData passes Protocol `parseDomainData`.
- payload data is not reshaped by Tool Bridge.
- empty/failure never invent DomainData.
- exact tool identity mismatch fails before DomainData creation.
- normalized outputs are detached/deep-frozen.

## RE/QC focus
Look for arbitrary transforms, fake data on empty/failure, Adapter SDK coupling, provider assumptions, source/freshness loss, mapping fallback/fuzzy match, raw failure text, mutable output, or bypass of Protocol DomainData validation.
