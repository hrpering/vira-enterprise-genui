# PR-085: Studio React runtime design parity

## Goal
Make published Studio experiences render through the same safe design semantics used by the Puck preview, without introducing Puck into production runtime dependencies.

## Scope
- add `@vira-enterprise-genui/studio-design-react` as a shared React-only adapter for the bounded Studio design grammar;
- move editor preview style resolution onto that shared adapter;
- add `@vira-enterprise-genui/studio-runtime-react` for Puck-free rendering of the current validated Studio runtime view;
- reconstruct canonical parent/slot hierarchy into trusted brand renderer slots;
- strip reserved Vira design props before invoking brand renderers;
- apply the same bounded design wrapper in editor preview and production rendering;
- expose declared component events through a narrow `emit(event, payload)` function backed by the existing Studio runtime session;
- reject undeclared event emission, bad registries, unregistered components, bad slot targets and renderer failures.

## Boundaries
- production renderer has no `@puckeditor/core` dependency;
- no raw CSS/HTML/JS/URL or renderer loading is introduced;
- runtime action/permission ownership remains in `@vira-enterprise-genui/studio-runtime` and Runtime Web/Core;
- renderer registry is host-owned trusted in-memory state and is never serialized;
- StudioDocument/StudioPublication schemas are unchanged.

## Acceptance criteria
- the same design props produce the same React wrapper style in Studio preview and runtime rendering;
- nested canonical slots render deterministically;
- brand renderers receive business props and rendered slots, never Vira design control props;
- declared events reach the existing Studio runtime dispatch path;
- undeclared events fail closed before dispatch;
- production React rendering does not depend on Puck;
- the PR is one commit on top of PR-084.
