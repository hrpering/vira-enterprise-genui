# PR-023: Layout Policy

## Goal
Define explicit semantic layout-family policy without introducing geometry, rendering, component, or brand concerns.

## Scope
- Define a bounded canonical set of layout families.
- Validate explicit `{ family }` policy input.
- Reject unknown families instead of silently choosing a fallback.
- Reject geometry/CSS/breakpoint/component/template fields.
- Return frozen serializable policy data.

## Out of scope
- Region placement or coordinates.
- Responsive breakpoints/geometry.
- Disclosure/visibility behavior.
- Component/brand selection.
- Runtime/DOM rendering.
- Model-driven layout selection.

## Acceptance criteria
- Supported families are explicit and immutable.
- Missing/unknown family fails closed.
- Policy contains no CSS/geometry/rendering implementation fields.
- No hidden default/model/brand selection exists.
- Output is immutable and serializable.

## RE/QC focus
Look for geometry leakage, implicit/default family selection, browser/CSS coupling, component/template ownership, hidden ranking/model behavior, mutable policy constants, or customer-specific family logic.
