# PR-039: Runtime Web User Event Reducer Bridge

## Goal
Route canonical user UI actions through Runtime Core's strict reducer/permission boundary and return data-only reduction results without executing effects.

## Scope
- Add `reduceUserEvent(input, idFactory)`.
- Reuse `createUserActionFromEvent` for fixed-user RuntimeAction construction.
- Pass runtime state and permission policy directly to Runtime Core `reduceRuntime`.
- Preserve Runtime Core state/effect/error ownership.
- Distinguish event-stage validation failures from runtime-stage canonical errors.
- Return immutable action/state/effect values only.
- Add tests and documentation.

## Out of scope
- Executing host/confirmation effects.
- DOM updates/state binding.
- Confirmation UX/tokens.
- Network/tool calls.
- Retry/queue behavior.

## Acceptance criteria
- Permission evaluation is never reimplemented in Runtime Web.
- Denied/invalid policies fail through Runtime Core and produce no executed effects.
- Confirm returns data-only confirmation effect with unchanged semantic state.
- Allowed host actions return data-only host effects.
- Allowed built-in runtime actions use Runtime Core's owning primitives.
- Event-stage failures do not reach reducer or consume IDs.

## RE/QC focus
Look for permission duplication/bypass, effect execution, confirm-as-allow, state mutation outside Runtime Core, event/runtime error conflation, source privilege, network/tool calls, or mutable reduction data.
