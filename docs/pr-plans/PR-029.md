# PR-029: Intent Adapter

## Goal
Map enterprise-native intent aliases into canonical Intent Protocol values through exact deterministic configuration.

## Scope
- Define versioned IntentAdapterContract.
- Define bounded exact source-key -> canonical target mappings.
- Reject duplicate source keys and unknown mapping fields.
- Add `adaptIntentAlias` with optional validated confidence/parameters.
- Delegate final Intent normalization to Protocol.
- Fail closed for unmapped aliases.
- Reject regex/glob/fuzzy/model/provider/endpoint/execution fields.
- Return frozen serializable outputs.

## Out of scope
- Intent classification or LLM inference.
- Regex/fuzzy matching.
- Prompt/provider configuration.
- Runtime authorization.
- Tool/API execution.
- Components/layout/rendering.

## Acceptance criteria
- Source matching is exact and deterministic.
- Unmapped aliases fail closed.
- Protocol owns canonical Intent validation.
- Confidence is never treated as authorization.
- Contract cannot contain executable or model-routing behavior.
- Caller-owned parameters are not retained mutably.

## RE/QC focus
Look for hidden inference, wildcard/regex matching, ambiguous duplicate mappings, confidence-as-permission, prompt/provider leakage, executable callbacks, mutable parameters, or duplicated Intent grammar.
