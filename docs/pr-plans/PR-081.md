# PR-081: Studio runtime bridge

## Goal
Execute published Studio interaction/view semantics through existing Vira runtime action and permission boundaries without changing ExperiencePlan or core/runtime package behavior.

## Scope
- add `@vira-enterprise-genui/studio-runtime`;
- revalidate incoming publication against canonical publish compilation;
- resolve exact current-view bindings through a trusted host data port;
- validate resolved values against component prop descriptors;
- expose a data-only current view model;
- dispatch published component events through Runtime Web `createStateBindingSession`;
- expose canonical host patch delegation;
- route host-reported success/empty/error outcomes using exact RuntimeAction id correlation;
- allow one pending action in MVP;
- add Pegasus end-to-end bridge tests.

## Out of scope
- changing Protocol ExperiencePlan;
- DOM renderer implementation;
- network/tool execution;
- data fetching inside Vira;
- multiple concurrent pending actions;
- general workflow orchestration;
- automatic host outcome inference.

## Acceptance criteria
- forged StudioPublication fails closed;
- binding values are type-checked before entering component props;
- Studio event dispatch cannot bypass Runtime Web permission/action handling;
- stale host outcomes cannot transition the Studio view;
- host patch handling delegates to the existing Runtime Web session;
- core/runtime packages remain unchanged.
