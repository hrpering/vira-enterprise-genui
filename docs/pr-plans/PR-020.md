# PR-020: Composition Planner

## Goal
Translate a canonical ExperiencePlan into deterministic semantic priority guidance without stealing Composer layout/region ownership.

## Scope
- Revalidate ExperiencePlan through Protocol.
- Derive `resolve`, `interact`, or `settled` semantic mode.
- Preserve required capability order as primary when blockers exist.
- Use explicit available capability order for interaction priority when no blocker exists.
- Preserve future capabilities as deferred.
- Return recursively frozen CompositionDirective data.

## Out of scope
- Semantic regions.
- Layout/disclosure policy.
- Component or brand selection.
- Runtime actions/permissions.
- DOM/CSS/responsive behavior.
- LLM/model ranking.

## Acceptance criteria
- Required capabilities always outrank available capabilities.
- No-blocker interaction priority is deterministic from explicit input order.
- Future capabilities remain deferred.
- Invalid ExperiencePlan input is rejected by Protocol.
- Output is immutable and serializable.
- No Composer/runtime/framework ownership leaks into planner.

## RE/QC focus
Look for hidden ranking/model inference, layout/region leakage, arbitrary reordering, component/action ownership, duplicated ExperiencePlan validation, mutable output, or customer/domain assumptions.
