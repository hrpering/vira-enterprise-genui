# PR-073: Experience Studio foundation contracts

## Goal

Create the editor-neutral, Puck-independent foundation for visual Experience Studio authoring without changing existing Vira runtime behavior or pretending visual documents are ExperiencePlan values.

## Scope

- Add `@vira-enterprise-genui/studio-schema`.
- Define versioned StudioExperienceDocument with views, nodes, bindings, interactions, and outcome routes.
- Represent nested visual structure through `parentId + slot + order` rather than Puck-specific structures.
- Require semantic component references and canonical JSON props.
- Add resource limits, reference integrity, cycle prevention, deterministic sibling ordering, and immutable normalization.
- Add `@vira-enterprise-genui/studio-compiler`.
- Compile a valid document into immutable StudioPublication plus exact component/action/binding dependency manifest.
- Document the complete Puck/Studio delivery plan.
- Add package-boundary rules and contract tests.

## Explicitly out of scope

- Puck or React dependencies.
- visual editor UI.
- brand component implementation registry.
- executing components or actions.
- Runtime Web changes.
- ExperiencePlan schema changes.
- arbitrary HTML/CSS/JavaScript, URLs, endpoints, callbacks, expressions, or iframes.
- persistence/auth/collaboration.

## Acceptance criteria

- StudioDocument is canonical JSON, editor-neutral, detached from caller mutation, deeply frozen, and JSON round-trippable.
- view/node IDs and semantic component references are validated deterministically.
- parent references cannot be missing, self-referential, cyclic, or ambiguously ordered.
- bindings target existing nodes and accept only explicit `state`/`domain` semantic sources.
- interactions target existing nodes, use bounded event names, and may route only `success`, `empty`, or `error` to existing views.
- unknown/executable/presentation escape-hatch fields fail closed.
- StudioPublication is deterministic and exposes a sorted exact dependency manifest.
- no existing production package behavior changes.
- this PR is exactly one commit on top of `phase-14/pr-072-mvp-completion-gate`.

## RE/QC focus

Look for Puck lock-in, hidden executable fields, URL/endpoint leakage, ambiguous tree ordering, orphan/cyclic nodes, unbounded authoring documents, dangling routes/bindings, duplicated targets, mutable outputs, Studio -> core dependency inversion, or language that conflates StudioPublication with ExperiencePlan.
