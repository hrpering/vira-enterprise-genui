# PR-076: Studio React/Puck shell

## Goal

Create the first executable Studio editor shell by assembling Puck Config render functions from a trusted host-owned renderer registry, without moving executable values into canonical Studio data.

## Scope

- Add `@vira-enterprise-genui/studio-react`.
- Depend on Puck 0.23 and the Studio Puck adapter only.
- Define a trusted in-memory renderer registry contract.
- Require exact renderer coverage for active catalog components.
- Reject missing, extra, non-function, accessor-backed, symbol, non-enumerable, or non-plain registry state.
- Snapshot renderer function references at session creation.
- Build Puck component field/category config from Studio Puck metadata.
- Strip Puck-only `id`/`puck` props before trusted renderer invocation.
- Preserve inline slot render values for trusted layout renderers.
- Add a thin React `<ViraExperienceStudio />` wrapper over Puck.
- Forward optional Puck `onChange` / `onPublish` callbacks without canonical mutation.
- Keep Puck CSS ownership with the host Studio application.

## Explicitly out of scope

- updating StudioDocument from drag/drop changes.
- Puck-generated id allocation/reconciliation.
- data-binding editor UI.
- action/flow editor UI.
- runtime preview bridge.
- persistence/auth/collaboration.
- injecting global CSS.
- loading components dynamically from URLs/import strings.

## Acceptance criteria

- no executable renderer enters Studio catalog/document/publication data.
- every catalog component has exactly one snapshotted trusted editor renderer.
- mutable registry replacement after session creation cannot swap the active renderer.
- renderer context strips Puck-only control props and is shallow-frozen.
- Puck config/data are constructed only after Studio adapter validation passes.
- the React shell is a thin wrapper and does not become a second Studio state engine.
- existing core/runtime packages remain independent from Studio/Puck.
- this PR is one commit stacked on PR-075.

## RE/QC focus

Look for executable renderer serialization, dynamic URL/import loading, registry getter invocation, stale/extra renderer acceptance, Puck control-prop leakage, duplicate Studio state ownership, hidden canonical mutation in onChange, global CSS injection, or Studio dependency inversion into existing core/runtime packages.
