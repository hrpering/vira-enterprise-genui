# PR-040: Runtime Web State Binding Session

## Goal
Keep one authoritative Runtime Core state reference across user-event reductions without duplicating task state or executing returned effects.

## Scope
- Add `createStateBindingSession(input, idFactory)`.
- Normalize initial RuntimeState, RuntimePermissionPolicy, and ActionAdapterContract at session creation.
- Keep exactly one current RuntimeState reference.
- Route events through the existing `reduceUserEvent` boundary.
- Advance current state only when Runtime Core returns the next revision.
- Retain the current reference only when a same-revision result is structurally identical.
- Leave current state unchanged for event/runtime failures.
- Reject impossible revision, experience identity, or same-revision semantic drift fail-closed.
- Add explicit disposal that prevents further event processing.

## Out of scope
- Effect execution.
- DOM updates or rerendering.
- asynchronous queues/concurrency.
- policy/adapter hot swapping.
- confirmation UX.
- network/tool calls.

## Acceptance criteria
- `RuntimeState.plan.state` remains the only task-state source of truth.
- Same-revision reductions do not replace the current state reference and cannot carry hidden semantic drift.
- Successful patch/lifecycle reductions atomically advance the current state.
- Deny/error/invalid events never advance state.
- Caller mutations after session creation cannot alter normalized session configuration.
- Disposed sessions fail before event reduction/ID allocation.
- No effect is executed by the session.

## RE/QC focus
Look for duplicated task state, revision drift, same-revision semantic drift, state advancement on confirm/deny/error, effect execution, mutable caller-reference retention, policy duplication, source privilege, hidden queues, or behavior after disposal.
