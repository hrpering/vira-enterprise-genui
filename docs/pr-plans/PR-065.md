# PR-065: Exact Component Allowlist

## Goal
Add a dependency-free Security primitive that authorizes validated component references by exact membership without taking ownership of component semantic grammar.

## Scope
- Add versioned `ComponentAllowlistPolicy`.
- Add bounded exact component-key entries.
- Add `createComponentAllowlistPolicy()` normalization/validation.
- Add `evaluateComponentAllowlist()` exact allow/deny decision.
- Permit empty allowlists as explicit deny-all.
- Reject duplicate keys, unknown fields, symbol/custom array state, sparse arrays, accessor-backed fields, oversized lists, and overlong keys.
- Freeze normalized policy output.
- Export the primitive from `@vira-enterprise-genui/security`.
- Add contract tests and documentation.

## Explicitly out of scope
- Runtime Web integration.
- deriving permissions from Component Adapter mappings.
- validating component semantic namespace grammar.
- wildcard/prefix/suffix/regex matching.
- capability authorization.
- action authorization.
- customer role/tenant claims.

## Ownership boundary
- Adapter SDK owns whether a component reference is semantically valid.
- Security owns whether a validated component reference is explicitly allowed.
- Runtime Web integration will be a later PR.

## Acceptance criteria
- Security remains dependency-free.
- empty policy denies valid bounded keys.
- exact allowed key permits.
- case/prefix/suffix variants deny.
- caller mutation cannot change normalized policy.
- malformed/custom/accessor/sparse inputs fail closed without executing getters.
- component semantic grammar is not duplicated in Security.

## RE/QC focus
Look for wildcard behavior, adapter-sdk/protocol imports, semantic namespace regex duplication, implicit allow defaults, caller-owned mutable references, getter execution, custom config ignored silently, unbounded arrays/strings, fuzzy matching, or capability/action policy conflation.
