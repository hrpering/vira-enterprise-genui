# PR-072: MVP Completion Gate

## Goal
Close the implementation plan with one cross-package public-surface integration gate and a precise MVP completion matrix, without changing production behavior.

## Scope
- Add a public API success path spanning Planner, Composer, Adapter SDK component resolution, Runtime Core, Runtime Web, Security network policy, Tool Bridge, Protocol DomainData validation, and Telemetry.
- Prove exact capability/component policy is present before DOM work.
- Prove a canonical Runtime Web user event becomes a host action without mutating state.
- Prove structured host/tool output normalizes back into canonical DomainData.
- Prove privacy-safe telemetry crosses only the trusted exporter port and shuts down deterministically.
- Add a deny path proving component denial before DOM work, action denial without state mutation/host effects, and exact network-method denial.
- Document closure evidence for Protocol, Planner, Composer, Adapter SDK, Runtime Core, Runtime Web, Web Component, React, Security, Tool Bridge, and Telemetry.
- Preserve the distinction between code-complete and release-candidate status while CI runner allocation remains unavailable.

## Explicitly out of scope
- changing production package behavior.
- adding new runtime features or experience schemas.
- model hosting, RAG, workflow orchestration, auth/billing, persistence, or message queues.
- visual/no-code Experience Studio.
- arbitrary HTML/JavaScript/iframe execution.
- provider-specific tool or telemetry transports.
- bypassing or weakening the repository `pnpm verify` release gate.

## Acceptance criteria
- the new integration test imports package public surfaces rather than internal implementation modules.
- the happy path crosses planning, composition, adapter resolution, runtime mount/action, network authorization, tool-result normalization, Protocol validation, and telemetry export.
- an unapproved component prevents any DOM-port call.
- a denied action does not mutate runtime state or produce a host action effect.
- a disallowed network method is denied exactly.
- no production files change.
- documentation names the existing package-level closure evidence and remaining CI blocker precisely.
- this PR is exactly one commit on top of PR-071.

## RE/QC focus
Look for test-only shortcuts around public APIs, implicit policy defaults, DOM/tool/network side effects before authorization, hidden telemetry payload widening, generated IDs/clocks outside explicit host factories, production changes, or language that incorrectly treats an unexecuted CI gate as passing.
