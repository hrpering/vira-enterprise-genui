# PR-008: Patch Protocol v1

## Goal
Define a small, typed, deterministic patch language for later runtime state/plan updates without implementing patch application yet.

## Scope
- Define versioned `Patch` with ordered operations.
- Support `set`, `remove`, `merge`, `append`, and `replace` operations.
- Define a constrained JSON Pointer-style path format.
- Reject prototype-pollution path segments and prototype-sensitive keys inside values.
- Canonically clone patch values and require object values for `merge`.
- Bound path length and operation count before expensive nested parsing.
- Add runtime parsing, a golden fixture, contract tests, and documentation.

## Out of scope
- Applying patches to runtime state.
- Existence/type checks against a target document.
- Permission checks or authorization.
- DOM diffing or renderer updates.
- Network synchronization or message queues.

## Allowed files
- `packages/protocol/src/patch/**`
- `packages/protocol/src/index.ts`
- `tests/contract/patch.test.ts`
- `tests/fixtures/protocol/patch.v1.json`
- `docs/protocol/patch.md`
- `docs/pr-plans/PR-008.md`

## Acceptance criteria
- A valid fixture parses, normalizes, and canonical JSON round-trips.
- Operations preserve source order.
- Invalid/unknown operations and fields fail deterministically.
- Patch paths reject empty segments, malformed escapes, control characters, and `__proto__`/`prototype`/`constructor` segments.
- Patch values recursively reject prototype-sensitive object keys; `merge` accepts canonical JSON objects only.
- Oversized operation arrays are rejected before nested operation parsing.
- No patch application, permission, UI, framework, or network behavior enters the protocol.

## RE/QC focus
Confirm the patch language is data-only and cannot become an execution channel. Inspect pointer parsing, prototype-pollution defenses in both paths and values, value normalization, operation ambiguity, resource bounds, and accidental runtime/renderer ownership.
