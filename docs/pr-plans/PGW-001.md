## Ownership

Protocol Gateway is a provider-neutral dispatch facade over provider-result normalizers already owned by `tool-bridge`. It does not own MCP/LangChain wire schemas and does not create a second Vira protocol.

```text
external provider result
      ↓
closed protocol dispatch
      ↓
existing tool-bridge normalizer
      ↓
canonical ExternalToolResult
```

## Boundary

`protocol-gateway -> tool-bridge` only.

## Invariants

- closed v1 protocol allowlist only;
- exact parity with existing tool-bridge normalizers;
- wrapper accessors/symbol state fail closed without getter execution;
- provider-specific validation details are normalized at the Gateway boundary;
- arbitrary secret/customer-content payloads are not reflected in Gateway errors;
- no HTTP/SSE/WebSocket/JSON-RPC/session/auth/discovery/tool-invocation lifecycle is introduced.

## Acceptance

1. MCP and LangChain dispatch preserve canonical tool-bridge results;
2. unsupported protocols and malformed wrapper state fail closed;
3. provider-specific nested paths/messages do not leak through Gateway errors;
4. latest-main diff contains only Gateway owner files plus its single package-boundary declaration;
5. exact reconciled-head hosted CI and adversarial review pass;
6. local repository CI remains deferred to the final all-phase integration SHA.
