# PR-074: Studio brand component catalog

## Goal

Define the safe serializable brand-component palette consumed by Experience Studio before Puck is introduced.

## Scope

- Add `@vira-enterprise-genui/studio-catalog`.
- Define versioned StudioComponentCatalog with semantic brand/catalog identities.
- Define exact component refs plus editor-only label/category/kind metadata.
- Define safe primitive/enum prop descriptors with explicit required/bindable flags.
- Define explicit parent slots and component events.
- Reject executable/implementation/network/presentation escape hatches through strict fields.
- Validate StudioExperienceDocument values against exact catalog components, props, slots, bindings, and events.
- Add Pegasus-style multi-view contract coverage.
- Add package-boundary dependency rules.

## Explicitly out of scope

- React/Vue/Web Component implementations.
- Puck dependency/config/data.
- runtime component loading.
- action-event authorization.
- data-source authorization or transforms.
- arbitrary HTML/CSS/JavaScript.
- URLs/endpoints/network execution.
- visual Studio application shell.

## Acceptance criteria

- Catalog values are deterministic canonical data, detached from caller mutation and deeply frozen.
- Component references are exact semantic references and unique within a catalog.
- Prop/slot/event metadata is bounded and duplicate-free.
- Enum options are bounded, explicit, and unique.
- Unknown/executable fields fail closed.
- A valid Pegasus-style StudioDocument passes exact catalog validation.
- Unregistered components, unknown/wrong-type props, invalid slots, unbindable bindings, static/binding conflicts, missing required props, and undeclared events fail closed.
- No existing core/runtime package behavior changes.
- This PR is one commit on top of Studio PR-073.

## RE/QC focus

Look for executable component leakage, hidden callbacks/imports/URLs, catalog-as-authorization confusion, weak component matching, prop type bypasses, binding/static ambiguity, invalid parent-slot acceptance, undeclared event acceptance, caller-object retention, unbounded metadata, or Studio -> core dependency inversion.
