# PR-047: Public Web SDK Instance + Mount Lifecycle

## Goal
Create the public `createViraGenUI` instance and a transactional single-active-experience mount lifecycle on top of the normalized Web SDK configuration.

## Scope
- Add `createViraGenUI(configurationInput)`.
- Reuse `createWebSdkConfiguration` as the only SDK config boundary.
- Add single-active `mount({ experienceId, plan, composition })`.
- Normalize RuntimeState before any DOM access and use its normalized plan as the source plan for both State Binding Session and DOM mount.
- Create State Binding Session before DOM mount.
- If declarative render validation or DOM host mount fails, dispose the provisional session and keep the SDK unmounted.
- Keep invalid render/composition failures distinct from DOM host/measurement failures.
- Add `currentState`, `isMounted`, `unmount`, `isDisposed`, and idempotent `dispose`.
- Allow remount after explicit unmount; reject concurrent/double mount.

## Out of scope
- public event dispatch.
- action/effect subscriptions.
- effect execution.
- update/patch convenience APIs.
- concrete browser DOM implementation.
- network/tool/model calls.

## Acceptance criteria
- SDK creation executes no DOM or action-ID methods.
- Invalid experience ID/plan fails before DOM access.
- Detached/forged composition reports `INVALID_RENDER_INPUT`, not a DOM host failure, and touches no DOM Port.
- One normalized ExperiencePlan anchors RuntimeState, State Binding Session, and mount integrity.
- Successful mount exposes the Runtime Core current state.
- A second mount while active fails without touching DOM.
- DOM host mount failure leaves no active SDK state.
- Unmount disposes session before mounted DOM and permits later remount.
- SDK dispose is idempotent and permanently blocks future mount.

## RE/QC focus
Look for duplicated config validation, raw plan/state duplication, declarative errors mislabeled as host failures, DOM access before state/render validation, partial active state on mount failure, non-idempotent cleanup, action/effect execution, hidden concurrency, or ability to mount after SDK disposal.
