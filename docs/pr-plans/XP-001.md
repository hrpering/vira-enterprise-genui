# XP-001 — Experience Pack v1 contract

## Objective

Introduce a transport-neutral distribution envelope for Vira experiences without changing the canonical Studio/runtime artifacts or depending on the parallel Studio product-completion stack.

## Authoritative base

- base branch: `main`
- base SHA at branch creation: `a24d677434458b99195343fc6d95ede30950882a`
- branch: `feat/experience-packs-v1`

## Reverse-engineering baseline

- `StudioDocument` and `StudioPublication` remain canonical authoring/publication artifacts.
- `packages/*` is already included by the workspace and TypeScript build.
- every package must be registered in `tooling/package-boundaries.config.mjs`.
- existing canonical parsers reject unknown fields and return deeply frozen values.
- the open Studio stack is independent; only the package-boundary registry file overlaps mechanically.

## Contract

Create dependency-free `@vira-enterprise-genui/experience-packs` with:

- schema versioning;
- `publisher/name` pack identity plus publisher namespace parity;
- release-semver pack and compatibility versions;
- bounded artifact descriptors;
- lowercase SHA-256 content digests;
- role-specific allowlisted media types;
- experience-only entrypoints;
- deterministic serialization;
- immutable canonical parsed output.

## Security/non-goals

Do not add:

- arbitrary HTML, JavaScript, JSX, CSS, WebAssembly, SVG, shell or executable payload declarations;
- secrets, credentials, API keys, backend endpoints or unrestricted URLs;
- file-system extraction paths;
- registry/network clients;
- OCI/ORAS libraries;
- Studio, Puck, runtime, React, security or telemetry dependencies;
- a second Studio document/publication format.

## OSS reconnaissance

OCI artifact guidance and ORAS are reference implementations for future registry transport. They remain outside XP-001 so Vira's pack contract stays provider- and transport-neutral.

## Verification

Required before merge:

1. package-boundary check;
2. lint;
3. strict typecheck;
4. contract/adversarial tests;
5. build;
6. existing Experience Studio and Pegasus checks;
7. browser verification/full verify gate;
8. independent reverse-engineering/QC pass against latest `main`;
9. diff and secret hygiene;
10. user-run local CI evidence.

## Merge rule

Do not merge until the final local test evidence is reviewed and the reverse-engineering verdict is `PASS`.
