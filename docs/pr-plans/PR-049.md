# PR-049: Public Web SDK Subscriptions

## Goal
Expose deterministic, fail-safe SDK notifications for canonical actions, data-only effects, state changes, and dispatch failures without turning subscriptions into an effect executor.

## Scope
- Add `sdk.on(event, listener)` for `action`, `effect`, `statechange`, and `error`.
- Return an explicit subscription result with idempotent `unsubscribe()`.
- Permit subscriptions before mount and preserve them across unmount/remount.
- Notify only after the owning State Binding Session returns.
- Emit success notifications in deterministic order: action, effects in reducer order, then statechange when revision advanced.
- Emit dispatch failures to `error` listeners while preserving the original dispatch result.
- Contain listener exceptions so one listener cannot change dispatch results or prevent later listeners.
- Reject reentrant `dispatch()` during notification before action-ID allocation rather than interleave revisions/events.
- Clear all listeners on SDK dispose and reject new subscriptions after disposal.

## Out of scope
- automatic host-action execution.
- confirmation handling.
- async/event queues.
- DOM rerendering.
- wildcard event names.
- network/tool calls.

## Acceptance criteria
- Listener callbacks never participate in permission/reducer decisions.
- Effect listeners receive RuntimeEffect data but the SDK does not execute semantic effects.
- Listener exceptions are contained and do not short-circuit notification order.
- Reentrant listener dispatch fails with `REENTRANT_DISPATCH` and consumes no action ID.
- Unsubscribe is idempotent.
- Subscriptions survive unmount/remount but not SDK disposal.
- Invalid event/listener registration fails closed.
- Dispatch return value remains identical regardless of listeners.

## RE/QC focus
Look for effect execution disguised as notification, listener exceptions escaping, reentrant dispatch/state-order drift, notification before reducer completion, statechange on same-revision results, subscription leaks after dispose, wildcard/default events, or listeners influencing authorization/state.
