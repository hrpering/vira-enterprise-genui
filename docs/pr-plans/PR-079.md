# PR-079: Studio actions and outcome flow

## Goal
Let no-code authors bind approved component events to existing enterprise Action Adapter events and route success/empty/error outcomes between Studio views.

## Scope
- add `@vira-enterprise-genui/studio-flow`;
- reuse Adapter SDK `ActionAdapterContract` as the exact action-event allowlist;
- validate all existing Studio interactions against registered action events;
- expose component event + action event + view options for a property panel;
- add transactional action binding commands;
- add success/empty/error route set/clear commands;
- preserve schema/catalog validation after every mutation;
- add Pegasus flight-search flow coverage.

## Out of scope
- endpoints, URLs, HTTP methods, callbacks or execution;
- runtime permissions/effects;
- loops, timers, retries, jobs or workflow orchestration;
- conditional expression language;
- model/tool invocation.

## Acceptance criteria
- undeclared component events fail closed;
- unmapped Action Adapter events fail closed;
- routes target existing views only;
- one component event has one exact action binding;
- outcome routes remain bounded by Studio schema;
- mutations are transactional and return fully validated StudioDocument values.
