# PR-075: Puck adapter

## Goal

Introduce Puck as a replaceable editor dependency and prove lossless view-level adaptation without making Puck Data a Vira protocol.

## Scope

- Add `@vira-enterprise-genui/studio-puck-adapter`.
- Pin `@puckeditor/core` exactly to `0.23.0`.
- Map Studio catalog primitive/enum/slot metadata to Puck editor field definitions.
- Convert one validated Studio view into Puck 0.23 `Data` with inline slot `ComponentData`.
- Convert edited Puck Data back by replacing one view in the surrounding StudioDocument.
- Keep canonical bindings/interactions outside Puck Data.
- Mark bound props as Puck `readOnly` fields during export.
- Reject legacy non-empty `zones` data.
- Reject unknown/unregistered Puck components and props.
- Require explicit mapping for Puck-generated ids that are not valid Studio node ids.
- Revalidate the complete StudioDocument and brand catalog after import.
- Add Puck-specific field-name collision checks.

## Explicitly out of scope

- executable Puck `Config.render` implementation registry.
- `<Puck>` application shell.
- persistence/auth/collaboration.
- runtime execution or preview.
- data-binding editor UI.
- action/flow editor UI.
- general Puck AppState serialization.
- legacy DropZone migration.

## Acceptance criteria

- Puck remains an adapter dependency only; no core/runtime package depends on it.
- nested Studio nodes export as inline slot data and round-trip back to the same canonical node graph.
- `zones` are never emitted and non-empty legacy zones fail closed.
- canonical bindings and interactions survive a view round-trip unchanged.
- edits that leave bindings/interactions dangling fail canonical revalidation.
- bound props are read-only in exported Puck component data.
- newly generated non-semantic Puck ids require explicit caller mapping.
- Puck-reserved/colliding field names fail before editor metadata is produced.
- one commit is stacked on Studio PR-074.

## RE/QC focus

Look for Puck format leakage into Studio contracts, hidden binding/action props, legacy-zone acceptance, arbitrary prop/component admission, generated-id leakage, stale id mappings, render-function leakage, silent deletion of canonical interactions/bindings, mutable canonical output, or a new dependency from existing core/runtime packages into Studio/Puck.
