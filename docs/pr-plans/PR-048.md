# PR-048: Public Web SDK Event Dispatch

## Goal
Expose active-experience UI event dispatch through the existing State Binding Session without executing Runtime Core effects.

## Scope
- Add `sdk.dispatch(event)`.
- Reject dispatch before mount and after SDK disposal without action-ID allocation.
- Delegate active dispatch directly to State Binding Session.
- Preserve `event`, `runtime`, and `session` failure stages from the owning Runtime Web/Runtime Core boundaries.
- Return canonical RuntimeAction, current RuntimeState, stateChanged, and data-only RuntimeEffect values on success.
- Keep `host-action` and `confirmation-required` effects unexecuted.

## Out of scope
- listener/subscription APIs.
- automatic host-action execution.
- confirmation UI.
- DOM rerender/update after state mutation.
- convenience patch APIs.
- network/tool calls.

## Acceptance criteria
- Dispatch cannot run when no experience is active.
- Disposed SDK fails before event processing/ID allocation.
- RuntimeAction source remains `user` through the existing event bridge.
- Allowed host action returns a data-only effect with no state mutation.
- Runtime patch advances the authoritative current state exactly once.
- Confirm and deny paths do not advance state.
- Existing event/runtime error details are not relabeled as SDK failures.

## RE/QC focus
Look for effect execution, source spoofing, state duplication, dispatch after unmount/dispose, action-ID allocation on SDK precondition failures, swallowed event/runtime stages, or direct permission logic in the SDK.
