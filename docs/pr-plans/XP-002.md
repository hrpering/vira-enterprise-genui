# XP-002 — Experience Pack prototype-pollution hardening

## Status

Planned from authoritative `main` `5266db3e56f4c3e2de4a91f3dcb70e3108dbd2d4`.

Branch: `fix/experience-packs-prototype-hardening`.

This is an owner-level hardening follow-up to XP-001. It was discovered while adversarially reviewing REG-001. The Registry PR must not patch Experience Pack semantics internally; canonical Pack input safety belongs here.

## Reverse-engineering finding

`@vira-enterprise-genui/experience-packs` already owns the Pack v1 schema and canonical parser. The parser correctly rejects many malformed values but currently has several JavaScript prototype-state gaps:

- `record()` validates an object's prototype but returns the original object, after which callers read fields such as `root.schemaVersion` directly; polluted `Object.prototype` fields/getters can therefore participate when an own field is absent;
- array-valued Pack fields are iterated by `length`/index without first proving every logical slot is an own data property, so sparse arrays can observe inherited numeric properties;
- canonical output arrays are built with `.push()`, which may invoke inherited numeric setters on `Array.prototype` when the next index is absent.

These are parser implementation safety issues. They do not justify a new Pack schema or Registry-specific Pack validator.

## Goal

Harden the existing canonical parser while preserving the XP-001 public contract and accepted canonical data.

```text
unknown Pack input
      ↓
existing Experience Pack parser
      ↓
own-data object snapshots + bounded logical array snapshots
      ↓
existing Pack semantic validation
      ↓
canonical frozen ExperiencePackManifest
```

## Intended changes

1. Change the internal plain-record helper so semantic code reads from a null-prototype snapshot containing only own data properties.
2. Reject symbol/accessor-backed object state through that helper rather than allowing direct inherited reads later.
3. Add a reusable bounded logical-array helper that:
   - requires a real Array with standard or null Array prototype;
   - snapshots the own `length` data descriptor once;
   - enforces the caller's logical length limit before allocation/traversal;
   - requires every semantic `0..length-1` slot to be an own data property;
   - never performs full array own-key/symbol/name enumeration.
4. Treat named/symbol array properties as non-semantic state: they are never read, executed, or copied into the canonical Pack. This preserves XP-001's semantic surface while avoiding unbounded Proxy `ownKeys` work.
5. Use the bounded logical-array helper for metadata tags, artifacts and entrypoints before any indexed reads.
6. Replace canonical output `.push()` writes with own-data `Object.defineProperty()` append semantics so inherited numeric setters are never invoked.
7. Preserve all existing Pack IDs, versions, media types, compatibility, deterministic serialization and output types.

## Explicit non-goals

Do not:

- change Pack schema version;
- change accepted canonical IDs/version/media types;
- promote named/symbol properties on array objects into Pack semantics;
- add Registry/Marketplace semantics;
- add transport, filesystem, network, signing or OCI behavior;
- add a JSON-text-only Pack API;
- introduce a second parser;
- weaken fail-closed validation of semantic Pack fields;
- make Registry depend on this branch before final reconciliation.

## Security invariants

- missing required Pack fields cannot be supplied through `Object.prototype`;
- inherited getters/data cannot satisfy semantic validation;
- sparse array holes cannot read inherited numeric values;
- array subclasses/custom prototypes fail closed;
- logical array length is snapshotted from its own descriptor and bounded before traversal;
- non-semantic array names/symbols are not enumerated or executed;
- parser-created canonical array writes do not invoke inherited numeric setters;
- arbitrary unknown Pack object fields remain rejected;
- output remains detached and deeply frozen;
- no secrets/content are newly reflected in validation errors.

## Acceptance

1. existing XP-001 contract tests remain valid;
2. regression: polluted `Object.prototype.schemaVersion` cannot satisfy an omitted Pack field and getter is not executed;
3. regression: sparse tags/artifacts/entrypoints cannot inherit values from `Array.prototype`;
4. regression: proxy `.length` getter is not executed because logical length comes from one own descriptor snapshot;
5. regression: oversized arrays fail before numeric entry inspection/allocation;
6. regression: named/symbol array metadata and Proxy `ownKeys` are never inspected;
7. regression: polluted `Array.prototype[0]` setter is not invoked while creating canonical output arrays;
8. accessor/symbol object state fails closed;
9. deterministic serialization remains unchanged for canonical input;
10. architecture/security review confirms this remains the canonical Pack owner rather than introducing Registry coupling;
11. local CI is deferred to the final all-phase integration gate per user instruction.
