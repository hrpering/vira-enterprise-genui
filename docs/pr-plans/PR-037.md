# PR-037: Runtime Web DOM Lifecycle

## Goal
Mount validated RenderModels through a transactional host DOM Port without hard-coding browser globals or dynamic component loading into Runtime Web core lifecycle.

## Scope
- Define trusted DOM Port/root/region/component-handle interfaces.
- Add `mountExperience(input, domPort)` using `prepareRenderModel` as the mandatory preparation gate.
- Preserve semantic region/component order.
- Commit only after all component mounts succeed.
- Roll back known component handles in reverse order and dispose root on mount failure.
- Add idempotent successful disposal.
- Contain host cleanup exceptions and never expose raw mount exception messages.
- Add tests and documentation.

## Out of scope
- Concrete browser DOM implementation.
- Dynamic imports/remote component loading.
- Component props/data bindings.
- Browser events/RuntimeAction construction.
- Accessibility/responsive behavior.
- Network/model/tool calls.

## Acceptance criteria
- No DOM Port call occurs if render preparation fails.
- Partial mounts are rolled back and never committed.
- Successful mounts preserve region/capability order.
- Dispose is idempotent and best-effort across all mounted handles.
- Host exception strings are not reflected in canonical errors.
- Runtime Web never treats semantic component refs as import paths/URLs.

## RE/QC focus
Look for partial-commit leaks, cleanup ordering bugs, non-idempotent dispose, raw exception reflection, preparation-gate bypass, dynamic import/URL interpretation, global DOM coupling, or component execution before integrity validation.
