# PR-028: Domain Adapter Contract

## Goal
Create a fail-closed Adapter SDK boundary that lets enterprise integrations declare the exact canonical DomainData domain/types their adapter contract accepts.

## Scope
- Define versioned DomainAdapterContract.
- Validate semantic adapter/domain identities.
- Validate bounded unique DomainData type allowlists.
- Add `normalizeDomainDataForAdapter` using Protocol's DomainData parser.
- Reject wrong-domain and unlisted-type payloads.
- Reject endpoint/credential/executable/permission transport fields.
- Return frozen serializable contract/data outputs.

## Out of scope
- HTTP/API/tool execution.
- Customer authentication or secrets.
- Runtime authorization/permissions.
- Raw response parsing.
- Domain-specific business rules.
- Component/rendering behavior.
- Runtime state/actions.

## Acceptance criteria
- Protocol remains owner of DomainData validation.
- Adapter contract cannot become a transport/execution/authorization configuration bag.
- Domain/type membership is never described or implemented as runtime authorization.
- Wrong domain or unlisted type fails closed.
- Duplicate/oversized type allowlists fail closed.
- Caller-owned input is not retained mutably.
- Outputs are immutable and serializable.

## RE/QC focus
Look for raw tool/API interpretation, endpoint/credential leakage, authorization confusion, arbitrary type bags, fail-open domain/type matching, duplicated DomainData parsing, mutable output, or hidden customer/business logic.
