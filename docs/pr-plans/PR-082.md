# PR-082: Studio AI-assisted authoring

## Goal
Allow a host-selected AI provider to propose bounded StudioDocument drafts using only the active enterprise authoring vocabulary, with mandatory validation and no automatic publish path.

## Scope
- add `@vira-enterprise-genui/studio-ai`;
- define a host-owned `generate(request)` provider port;
- bound and validate prompt input;
- fix experience and recipe identity outside model control;
- expose only active component metadata, binding sources, and Action Adapter event aliases to the provider;
- optionally include one fully validated base document for editing workflows;
- validate candidate output through component, binding, action, and flow gates;
- redact provider exceptions;
- return a validated StudioDocument draft only;
- add provider/vocabulary/deny-path tests.

## Out of scope
- provider SDKs, model configuration, credentials or network clients;
- prompt storage or telemetry;
- automatic retry/repair loops;
- arbitrary HTML/CSS/JavaScript/endpoints;
- RuntimeAction construction/execution;
- automatic preview/publish/deploy.

## Acceptance criteria
- provider cannot alter the requested experience/recipe identity;
- unregistered component, binding source, action alias, prop, event or route fails closed;
- provider exceptions do not leak raw error text;
- provider request contains no endpoint/permission/runtime implementation data;
- valid candidate output is immutable canonical StudioDocument data;
- no core/runtime package behavior changes.
