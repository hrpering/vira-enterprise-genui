# PR-077: Puck canonical authoring session

## Goal

Turn Puck drag/drop/reorder output into transactional canonical StudioDocument updates with explicit host-owned identity allocation.

## Scope

- Add `@vira-enterprise-genui/studio-puck-authoring`.
- Create a stateful but bounded authoring session around one Studio view.
- Snapshot validated initial StudioDocument/catalog state.
- Export the current view through the existing Puck adapter.
- Reconcile incoming Puck Data back into the canonical document transactionally.
- Scan Puck component identity/slot structure before node-id allocation.
- Bound node count before recursive canonical import.
- Require unique Puck ids within the active view.
- Require an explicit host `allocateNodeId` function for non-semantic Puck ids.
- Validate allocator output and reject collisions.
- Cache Puck-id -> Studio-id mappings for session stability.
- Contain allocator exceptions without reflecting provider error text.
- Commit the new canonical document only after full Studio schema + catalog validation succeeds.

## Explicitly out of scope

- binding editor UI.
- action/flow editor UI.
- silently removing dangling bindings/interactions after visual deletion.
- persistence/collaboration/version history.
- runtime preview bridge.
- AI authoring.
- hidden/global id generation.

## Acceptance criteria

- visual sibling reorder becomes deterministic Studio sibling order.
- newly inserted Puck nodes receive one stable caller-owned canonical id.
- repeated reconciliation of the same Puck id does not invoke the allocator twice.
- invalid/throwing/colliding allocator results fail closed.
- unregistered components fail before id allocation.
- failed import leaves the previous canonical document unchanged.
- deleting a node still referenced by an interaction/binding fails instead of deleting behavior implicitly.
- caller mutation of initial document cannot mutate active session state.
- one commit is stacked on PR-076.

## RE/QC focus

Look for hidden/random id generation, allocator exception leakage, unbounded identity scanning, duplicate Puck ids, non-transactional canonical mutation, silent dangling-reference cleanup, stale mapping ambiguity, Puck state becoming persistence truth, or dependencies from existing core/runtime packages into Studio authoring.
