# DSC-001 — DTCG to Studio design compiler contract

## Objective

Add a provider-neutral Design System Compiler that translates a strict, explicitly supported subset of stable DTCG 2025.10 design tokens into the existing `StudioDesignCatalogOptions` contract. It must not create a second Vira design model, modify `studio-design`, or couple the compiler to Studio editor/runtime implementations.

## Authoritative base

- base branch: `main`
- base SHA at branch creation: `6095198f8d0abad26b31774e66dccc0051d1393f`

## Reverse-engineering baseline

- `@vira-enterprise-genui/studio-design` already owns the canonical design-control surface.
- `StudioDesignCatalogOptions` owns component selection, color mode/palette, registered fonts, gradient permission, shadow presets and layout presets.
- `createStudioDesignCatalog()` remains the canonical operation that augments a validated component catalog with design props.
- Studio currently allows at most 64 palette colors and 32 fonts.
- Studio colors are strict `#RRGGBB`; alpha colors and arbitrary CSS color expressions are outside the canonical contract.
- Studio registered font values are bounded strings and are applied through the trusted design renderer.
- the new compiler must depend downward on `studio-design`; `studio-design` must never depend on the compiler.

## OSS/spec reconnaissance

- DTCG 2025.10 is the stable published Design Tokens format used as the external interchange reference for this PR.
- the 2026 DTCG material is draft and is not an implementation target.
- DTCG color values carry `colorSpace`, `components`, optional `alpha`, and optional six-digit `hex` fallback.
- DTCG group `$type` provides an inherited token type unless a token overrides it.
- DTCG groups process local tokens before `$root`, then extended tokens, then nested groups. DSC-001 rejects `$extends`, so its supported traversal is local tokens → `$root` → nested groups, deterministic within each phase.
- DTCG `fontFamily` values may be strings or ordered arrays of strings.
- Style Dictionary supports DTCG syntax, but full support for the latest DTCG revision remains an evolving adapter concern.
- DSC-001 therefore adds no Style Dictionary production dependency. It can be considered later as a replaceable source-normalization adapter.

## Compiler v1 scope

The compiler consumes JSON-like DTCG token input and returns existing `StudioDesignCatalogOptions` plus immutable deterministic compile metadata.

Supported semantics:

- literal `color` tokens;
- literal `fontFamily` tokens;
- inherited group `$type`;
- explicit token `$type` override;
- `$root` tokens;
- DTCG local-token → `$root` → nested-group processing order;
- deterministic lexicographic ordering within each supported processing phase;
- unsupported token types ignored and counted;
- existing Studio palette/font output limits.

Color compilation:

- opaque numeric `srgb` components are converted deterministically to `#RRGGBB`;
- an sRGB `hex` fallback must match numeric components when both are present;
- unsupported color spaces require an opaque six-digit `hex` fallback;
- non-opaque colors are rejected because Studio has no alpha color contract;
- unsupported spaces without exact fallback fail rather than being approximated.

Font compilation:

- one DTCG font-family string becomes one registered Studio font value;
- an ordered array becomes one bounded comma-separated fallback stack;
- every family name uses a deliberately narrow safe grammar;
- CSS declarations, URLs, functions, control characters and references are rejected.

## Explicit non-goals

Do not:

- implement the full DTCG resolver specification;
- silently resolve aliases, curly-brace references, JSON Pointer `$ref`, `$extends`, or reference cycles;
- interpret provider-specific `$extensions` in the core compiler;
- guess token types from names or values;
- compile arbitrary CSS, font URLs, remote assets, executable content or network resources;
- add Figma/Tokens Studio/provider-specific contracts to the core compiler;
- add Style Dictionary as a runtime dependency;
- add a new design bundle or media type;
- modify the canonical `studio-design` package or its design-prop model;
- depend on Experience Packs or Registry.

Unsupported reference semantics and provider-specific reserved data must fail explicitly instead of producing approximate design output.

## Intended package boundary

```text
DTCG 2025.10 token source
        ↓
@vira-enterprise-genui/design-system-compiler
        ↓
StudioDesignCatalogOptions
        ↓
existing createStudioDesignCatalog()
        ↓
existing Studio design/runtime path
```

Allowed package dependency:

```text
design-system-compiler -> studio-design
```

No dependency is allowed on Puck, React, runtime, network, filesystem, Experience Packs or Registry.
