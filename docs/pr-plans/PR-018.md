# PR-018: Planner Capability Resolver

## Goal
Resolve explicit missing/conflicting state blockers into deterministic semantic capability buckets without component selection or inferred capabilities.

## Scope
- Accept explicit missing/conflicting semantic field lists.
- Map blocker fields through explicit unique field -> Capability requirements.
- Fail closed when a blocker is not mapped.
- Validate optional available/future Capability lists.
- Reject ambiguous blockers, duplicate mappings, and duplicate capability identities.
- Bound all input arrays before recursive canonical parsing.
- Enforce Protocol's ExperiencePlan total capability limit on resolved output.
- Return immutable PlannedCapabilities-compatible buckets.

## Out of scope
- Component/brand mapping.
- Layout/composition.
- LLM/model inference.
- Domain/API/tool execution.
- Runtime permissions.
- ExperiencePlan creation.

## Acceptance criteria
- Active blockers map only to explicitly configured capabilities.
- Unmapped blockers fail closed.
- No capability can occupy multiple configured semantic positions.
- Required output order follows explicit requirement configuration order.
- No blockers means no inferred required capabilities.
- Output cannot exceed ExperiencePlan's canonical capability limit.
- Outputs are frozen canonical data.
- No component/framework/network/customer behavior leaks into planner.

## RE/QC focus
Look for capability invention, component leakage, fail-open unmapped blockers, duplicate bucket ambiguity, blocker precedence bugs, ExperiencePlan incompatibility, source/customer assumptions, executable rule logic, mutable outputs, unbounded arrays, or runtime permission leakage.
